# Connections

Проектные connections (auth к qadam'ам). Заводятся в UI, привязываются к шагам
по `externalId` (`ap_list_connections` → поле `auth`). Секреты — только в UI.

AI-провайдеры платформенные (общие на всю платформу), connections — проектные.

| Connection | Qadam | Тип auth | Назначение |
|------------|-------|----------|-----------|
| `AI Qadam Events (dev)` | `@aiqadam/qadam-telegram-bot` | Bot Token | **отдельный бот-аккаунт** только под ивенты (Q4); `externalId` `TZTlXaCEO2hEvimUowbSA` |

Один вебхук на бот-токен: описание триггера `new_telegram_message` говорит прямо —
«One trigger per bot token». Поэтому токен существующего `aiqadam-telegram-bot`
сюда не подходит.

Заведён 2026-09-08. Фактическое имя connection в UI — `AI Qadam Events (dev)`,
а не `events-bot`, как планировалось: привязка к шагам идёт по `externalId`,
поэтому имя ни на что не влияет, но здесь оно записано так, как в инстансе.

## Токен бота как значение шага (W2, устарело — см. ниже)

проверка `initData` подставляла токен в `text` у `crypto / hmac-signature`
(тогда — во флоу `fn-verify-init-data`, удалён в W22)
шаблоном `{{connections['TZTlXaCEO2hEvimUowbSA']}}`, а **не** через параметр `auth`:
`crypto` qadam'у авторизация не нужна, токен нужен ему как данные (STF-2, первый HMAC
цепочки). Проверено прогоном на инстансе 2026-09-08. В репозитории — только
externalId connection.

**С 2026-09-09 (W8) источник токена — `{{variables['BOT_TOKEN']}}`, не
`{{connections[...]}}`** (реальный баг с байт-в-байт несовпадением секрета,
[ADR-0008](../docs/adr/0008-bot-token-as-variable-not-connection-template.md)),
**а с 2026-09-09 (W16) сам HMAC считается внутри CODE step через `node:crypto`,
а не отдельным `crypto` qadam'ом** ([ADR-0010](../docs/adr/0010-unsandboxed-code-step-for-crypto.md)).
Абзац ниже про утечку в логах остаётся верным для обоих источников токена —
изменился только формат подстановки, не факт утечки самого `BOT_TOKEN` (он всё
ещё *вход* шага).

**Но «не в репозитории» ≠ «защищено».** Токен попадает во входы этого шага,
а производный от него секретный ключ Telegram — в его вывод, и оба лежат
открытым текстом в логе каждого прогона. Кто читает логи проекта — подделывает
`initData` для любого `telegram_id`, то есть обходит STF-2 целиком.
Цена названа в [ADR-0005](../docs/adr/0005-secrets-visible-in-run-logs.md);
следствие практическое: доступ к проекту выдаётся как доступ к токену,
а логи прогонов не выносятся из платформы.
