# Эталоны встраиваемой логики

Заведено [ADR-0012](../../docs/adr/0012-end-to-end-flows-instead-of-subflow-functions.md).

С переходом на end-to-end флоу переиспользуемая логика больше не живёт в
subflow'ах — она **встраивается** в тела флоу CODE-шагами. Чтобы копии не
разъехались, здесь лежит эталон каждой такой логики и список флоу, которые
её встраивают.

## Правила

1. **Копия обязана совпадать с эталоном побайтово.** Не «по смыслу» — побайтово.
   Проверяется механически: `ap_read_step_code` по каждой копии плюс diff.
2. **Правка эталона — правка всех копий в том же пакете работ.** Список
   встраивающих флоу указан в каждом файле; если он устарел, это дефект
   каталога, а не мелочь.
3. **Новый вызывающий — новая строка в списке.** Добавили копию, не отметив —
   следующая правка эталона её не найдёт.
4. Это единственное место в `catalog/`, которое **предписывает**, а не
   описывает. Остальной каталог по-прежнему отражает реальность.

## Почему так, а не subflow

Вызов `callFlow` стоит ≈1,0–1,2 с даже в режиме `inline`, CODE-шаг — ≈0,06 с
(замеры [Q28](../../docs/OPEN-QUESTIONS.md#q28)). На горячем пути вызовы
занимали 70 % прогона. Цена решения — дублирование и риск дрейфа — названа
в ADR-0012 прямо.
