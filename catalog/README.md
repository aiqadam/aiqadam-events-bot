**Источник правды проекта в git.** Живые flows и таблицы строятся в Qadam Flow
через **MCP**, а этот каталог — их человеко- и агенто-читаемая спека.

Практика взята из `qadam-flow-project-template` (BPM Hero), см.
[ADR-0004](../docs/adr/0004-catalog-instead-of-flow-export.md).

> Каталог — **спека, а не артефакт для авто-редеплоя**. Работаем только через MCP и UI:
>
> - собрать/изменить flow → MCP (`ap_build_flow`, `ap_add_step`, `ap_update_step`);
> - зафиксировать состояние в git → агент читает живой flow (`ap_flow_structure`,
>   `ap_read_step_code`) и обновляет соответствующий `.md`;
> - перенести в другой проект (`events-dev` → `events-prod`) → агент читает каталог
>   как спеку и **пересобирает** flows через MCP.

## Структура

```
catalog/
  project.md        — идентичность проекта (project_id, URL) — без секретов
  overview.md       — карта: flows, таблицы, связи
  flows/
    _TEMPLATE.md    — формат описания flow
    <flow>.md       — по одному на каждый построенный flow
  tables/
    _TEMPLATE.md    — формат описания таблицы
    <table>.md      — по одной на каждую таблицу
  variables.md      — имена Variables (значения — НЕТ)
  connections.md    — какие проектные connections нужны
```

## Правило синхронизации

После **любого** изменения flow через MCP:

1. `ap_flow_structure` (+ `ap_read_step_code` для CODE-шагов) — снять актуальную структуру;
2. обновить `flows/<flow>.md` по формату `_TEMPLATE.md`;
3. при изменениях в таблицах/переменных/связях — обновить `tables/`, `variables.md`, `overview.md`;
4. коммит: feature-ветка → PR.

**Каталог и живой проект должны совпадать.** Расхождение = каталог устарел,
привести в соответствие. Каталог, описывающий то, чего в проекте нет, хуже пустого:
по нему принимают решения.

## Чего в каталоге не бывает

Значений секретов, токенов, содержимого connections. Всё это живёт в UI платформы.

Значение несекретной Variable (`BOT_USERNAME`, `MINIAPP_URL`) в каталоге допустимо
и полезно: по нему собираются шаги флоу, а публичным оно является и без нас.
Критерий простой — попадание значения в git не должно ничего компрометировать.
`QR_SIGNING_KEY` под это не подходит и в каталог не попадает никогда.
