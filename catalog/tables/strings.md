# Table: strings

- **Назначение**: рабочая копия локализации на инстансе (I18N-2). Источник правды —
  `i18n/{ru,uz,en}.json` в репозитории, сюда их заливает `i18n-sync` (W3).
- **externalId таблицы**: `qi6bBTL7plRGBgFUfli8w` · **внутренний id**: `6965qPeAeAWTWJtna835A`

| Field | Type | externalId | field id | Назначение |

## Заметки

- **Кто пишет:** только флоу [`i18n-sync`](../flows/i18n-sync.md) (`yIMvjNdxj27jv4fZF4fFp`).
  Правка значения руками в UI живёт до следующего суточного прогона — он вернёт
  текст из `i18n/*.json`. Проверено: испорченное вручную значение восстановлено
  следующим же прогоном.
- **Сколько строк должно быть:** ровно по одной на каждую пару `(key, lang)`
  из `i18n/*.json`. Абсолютное число здесь не фиксируется — оно меняется
  с каждым ключом, и сверять содержимое надо с файлами, а не с этим текстом.
  На 2026-09-08 файлы дают 203 `ru` + 202 `uz` + 202 `en`; разница в один ключ —
  фикстура `_selftest.fallback`, заведённая только в `ru`.
- **Строки может удалить кто угодно, и это лечится прогоном.** 2026-09-08
  из таблицы пропали четыре строки (`checkin.ok`, `checkin.already`),
  засеянные и потом убранные соседним пакетом; следующий прогон `i18n-sync`
  восстановил их из файлов. Расхождение таблицы с репозиторием — не авария,
  а нормальный вход для синхронизации.
- Уникальность `(key, lang)` — соглашение `i18n-sync`; БД её не держит.
  Дубли, если появятся, вычищаются следующим прогоном: остаётся самая ранняя
  запись (ADR-0003).
- **Пустых `value` в таблице не бывает.** Отсутствующий перевод — это
  **отсутствующая строка**, а не строка с пустым значением: `fn-t` различает
  эти случаи только так, и пустое значение сломало бы фолбэк в `ru`
  ([I18N.md](../../docs/I18N.md#пустых-значений-в-strings-не-бывает)).
- Строк с `lang` вне `ru`/`uz`/`en` быть не должно — `i18n-sync` их удаляет.
