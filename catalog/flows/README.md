# Flows: как читать этот каталог

Живое состояние flows проекта `events-dev`. Формат файла — [_TEMPLATE.md](_TEMPLATE.md).
Каталог обновляется после **каждого** изменения flow через MCP
([ADR-0004](../../docs/adr/0004-catalog-instead-of-flow-export.md)).

## Два идентификатора у флоу — как у таблиц

| Где | Какой ключ | Как узнать |
| --- | --- | --- |
| MCP-инструменты (`ap_flow_structure`, `ap_test_flow`, `ap_lock_and_publish`) | **flowId** | `ap_list_flows` |
| `flow` в `subflows / callFlow` (`{"externalId": ...}`) | **externalId** флоу | `ap_resolve_property_options` для `propertyName = flow` |

Оба записаны в каждом файле. **Все id — свои у каждого проекта**: при пересборке
в `events-prod` (W15) сначала создаются subflow'ы, потом по их новым externalId
настраиваются вызовы.

## Проверенные факты про subflow'ы (2026-09-08, пакет W2)

1. **Вход subflow'а лежит в `trigger['output'].data`, а не в корне.** `callFlow`
   передаёт `{ data: <payload>, callbackUrl: ... }`. Ссылка `{{trigger['output'].eventId}}`
   молча даёт `undefined` — тест через `ap_test_flow` с плоскими sample data проходит,
   а реальный вызов ломается. Ссылаться только через `.data.`.
2. **Ответ `callFlow` — `{ status: 'success', data: <тело respond> }`.** То есть поле
   ответа читается как `{{step_N['output'].data.field}}`.
3. **Callee обязан быть published + ENABLED**, иначе его нет в dropdown'е `flow`.
   Отсюда порядок сборки: листья (`fn-t`, `fn-fmt-time`, `fn-sign-qr`) публикуются
   раньше тех, кто их вызывает.
4. **Вызванный subflow исполняется в PRODUCTION даже когда вызывающий тестируется.**
   Ошибка внутри callee видна не в отчёте теста, а по ссылке на его собственный run.
5. **`ap_validate_flow` считает `{{variables['NAME']}}` битой ссылкой** —
   `"references {{variables...}} which does not exist in the flow"`. Это ложное
   срабатывание: те же шаги на прогоне подставляют реальные значения (проверено
   сравнением HMAC с контрольным значением на пустом ключе). Флоу с этим замечанием
   публикуются штатно, но **само замечание нельзя использовать как признак опечатки
   в имени переменной** — опечатка даёт пустую строку и тоже «валидна».
6. **`ap_test_step` не всегда переигрывает предшественников**: на шаге в середине
   цепочки предыдущие шаги вернули `{}`. Для сквозной проверки — `ap_test_flow`.
7. **MCP не отдаёт inputs PIECE-шагов.** `ap_read_step_code` работает только с CODE,
   `ap_get_run` показывает только outputs. Значит конфигурацию PIECE-шага
   (какой шаблон стоит в каком поле) ревью читает **только в UI**, а по MCP
   проверяется лишь поведением. Для `fn-verify-init-data` это оставляет ровно одну
   непроверяемую чтением вещь — [Q16](../../docs/OPEN-QUESTIONS.md#q16).
8. **Одиночное действие можно прогнать без флоу** — `ap_run_action`. Так проверены
   семантика `crypto / hmac-signature` и поведение фильтров `tables-find-records`
   ([Q15](../../docs/OPEN-QUESTIONS.md#q15)): дешевле, чем собирать пробный флоу.
9. **`ap_delete_records` работает в пределах одной таблицы за вызов.** Список id
   из трёх таблиц удалит только строки одной из них, молча.

Эти же факты сведены в
[ARCHITECTURE](../../docs/ARCHITECTURE.md#subflowы-на-практике--проверено-на-инстансе-2026-09-08-w2)
— там их ищет следующий пакет, идущий по порядку чтения.

## Соглашения subflow-«функций» (`fn-*`)

- **Один вход — один `respond`.** Ветвлений нет: вместо ROUTER'а невалидный вход
  нормализуется в Code step, а решение принимает последний Code step. Один путь
  исполнения на все входы — меньше мест, где отказ забыли.
- **Не падаем на мусорном входе.** Возвращается `{ valid|found|allowed: false, error|reason }`.
  Исключение — `fn-sign-qr`: подписать пустой `eventId` хуже, чем упасть.
- **Сентинелы вместо пустых фильтров.** Пустой `event_id` в `tables-find-records`
  превратился бы в выборку чужих строк, поэтому подставляется `-` (вне алфавита
  slug'а и `telegram_id`); для фильтра `in` — `!no-key` (пустой список валит шаг).
- **Шаг не читает больше строк, чем ему нужно.** Проекции колонок у `tables` qadam
  нет: `find-records` возвращает все поля строки, и они целиком уезжают в лог
  прогона. Сузить можно только фильтром — и это обязанность шага, а не пожелание
  ([ADR-0005](../../docs/adr/0005-secrets-visible-in-run-logs.md),
  [Q17](../../docs/OPEN-QUESTIONS.md#q17)).
- **Code step — чистая функция.** Ни сети, ни записи в БД; HMAC — `crypto` qadam.
- **`cells` разбираются по `fieldName`, а не по id поля** — id разные в каждом
  проекте, `fieldName` приезжает в той же ячейке.
