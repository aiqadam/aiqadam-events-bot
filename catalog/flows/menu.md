# Flow: menu

- **Статус**: ENABLED (published)
- **Триггер**: `@aiqadam/qadam-subflows : callableFlow` — вызывается из `tg-router`
  (`route: menu`: голый `/start`, `/start` с неразобранным payload, любая
  незнакомая команда — [ADR-0025](../../docs/adr/0025-start-only-commands-ban.md))
- **Назначение**: меню-хаб — одно сообщение с inline-кнопками, набор которых
  зависит от ролей пользователя (гость / организатор / контролёр). Заменяет молчание на
  холостой `/start` ([W34](../../docs/work/W34-menu.md)).
- **Flow ID (MCP)**: `1DORFhP9F3W00KpKz5wDw` · **externalId**: `BOLkFV1GreF8r7opvDCVo`

## Заметки

- **Кнопки `web_app` собираются из `MINIAPP_URL`**: `#/events` (все роли —
  каталог и «Мои билеты» — один экран, открывается первым табом),
  `#/manage` (организатор — свой список с входом в правку, W51) и
  `#/manage/new` (организатор — сразу форма создания, вердикт W49).
  Кнопки сканера в чате нет: сканер — рядом с ивентом в Mini App по правам
  плюс кнопка «Открыть сканер» на конкретный ивент в accept-карточке
  контролёра (W50). Права проверяет не страница, а `manage-api`/`checkin-api`.
- **Staff-фильтр — defense-in-depth в CODE step_4**, не в tables-запросе: шаг_2
  читает все staff-строки пользователя без фильтра `revoked_at`, CODE step_4
  постфильтрует `r.revoked_at === ''` (паттерн W18, [Q25](../../docs/OPEN-QUESTIONS.md#q25)).
  Дополнительно: только опубликованные ивенты (`byId[r.event_id]`) и только
  будущие (`notPast` по `ends_at` или `starts_at`). Флаг `isController` больше
  не выбирает ивент для кнопки — только текст и `role`; отозванный контролёр
  падает в гостя (проверено перебором 5 комбинаций, W50).
- **Порядок кнопок фиксирован, по одной в ряд**: гость — [`Ивенты`];
  организатор — [`Управление ивентами`, `Ивенты`, `Создать ивент`]
  (W52: управление первым — овнер чаще открывает свой список);
  контролёр — [`Ивенты`] со своим текстом; двойная роль — объединение
  (кнопки овнера).
  `Управление ивентами` ведёт на список `#/manage` (вход в правку без команд,
  W51 — решение владельца 2026-09-19, поправка к вердикту W49).
  Гость → 1 кнопка, организатор → 3. Общего заголовка «Что дальше?» нет: у каждой роли свой
  лид (`menu.lead_guest` / `menu.lead_owner` / `menu.lead_controller`,
  вердикт W49).
  Каталог ивентов — экран (ADR-0023), а не чат-лист: своих колбэков у меню
  не осталось, `myreg:list` заменён экраном (W43, [Q57](../../docs/OPEN-QUESTIONS.md#q57)).
  Ключи `menu.title`, `menu.btn.my_events`, `menu.btn.my_tickets`,
  `menu.btn.scanner` остались в `i18n/ru.json` как архив корпуса, живые флоу
  их не читают (W50).
- **«Создать ивент» — видимость, а не авторизация** ([ADR-0024](../../docs/adr/0024-staff-by-chapter-event-staff-checkin.md)):
  кнопка показывается по строке в [`staff`](../tables/staff.md), даже если у
  организатора ещё нет ивентов. Само правило прав живёт в одном месте —
  `manage-api`; кнопка на чужой чаптер всё равно упрётся в `403`.
- **`badPayload`** — флаг из `tg-router` (`/start` с неразобранным payload):
  меняет преамбулу с приветствия на `start.bad_payload`.
- **Тексты — через `inputs.texts`** (ADR-0014), ключи `menu.*` и `start.*`.
  `format: None` — текст без разметки, экранирование не нужно.
- **«Мои ивенты» заменены «Создать ивент» обратно (W50, вердикт W49)** —
  W13 сводил обе кнопки на `#/manage`, оставив одну; вердикт вернул создание
  из чата: кнопка ведёт сразу на форму `#/manage/new`, а кнопки создания
  в списке Mini App нет. Ключ `menu.btn.my_events` остался в `i18n/ru.json`
  как архив, живые флоу его не читают.
- **Флоу собран мимо процесса и обнаружен при аудите** — принят ретроактивно
  как W34. Предыдущая запись в журнале W34 («сверка подтвердила, не создан»)
  была неверной.
- **Грабли: черновик дрейфует мёртвым входом.** `ap_update_step` мержит
  top-level ключи входа, удалить ключ нечем — снесённый `ownerRecords: ""`
  вернулся в черновик `step_4` слиянием (код его не читает, безвредно).
  Опубликованное и `flows/menu.json` при этом чистые. Перед следующей
  публикацией сверить тройку черновик/опубликованное/файл (W51, ревью).
