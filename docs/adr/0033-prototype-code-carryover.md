# 0033. Перенос кода прототипа в продукт для сведения к эталону

**Статус:** принято 2026-09-18 владельцем. **Приостанавливает**
[ADR-0026](0026-prototypes-design-artifact.md) п. 4 («код продукта из прототипа
не копируется») **только на время пакета W50** и только для расхождений,
зафиксированных вердиктом владельца по проходу прототипа (журнал W49).
Сам ADR-0026 не правится задним числом.

## Контекст

Прототип — целевой эталон ([ADR-0027](0027-prototype-as-target-reference.md),
покрытие — [ADR-0031](0031-prototype-covers-extended-v01.md)). Проход владельца
(W49) зафиксировал расхождения живого продукта с эталоном в обе поверхности:

- чат `menu`: гостю две кнопки вместо одной; общая кнопка «Сканер» в чате
  (вердикт: чекин только контекстный — рядом с ивентом); у овнера «Мои ивенты»
  на список (вердикт: создание из чата — сразу форма `#/manage/new`, а кнопки
  создания в списке Mini App нет);
- общий заголовок меню «Что дальше?» для всех ролей (вердикт: у гостя и
  контролёра свои тексты без заголовка, у овнера свой);
- accept/notify контролёра дублируют «Вы контролёр»; сканер в чате вместо
  кнопки «Открыть сканер» на конкретный ивент;
- визард «Где и когда»: шит ссылки и превью с пином удалены вердиктом;
  осталось голое поле ссылки + живой разбор на вводе, тогл формата
  Онлайн/Офлайн, строгая валидация офлайна.

П. 4 ADR-0026 требует переписывать каждый экран заново по доказательству
замысла. Владелец 2026-09-18 решил иначе: «фактически прототип скопировать
и заставить его работать, левое убрать». Переписывание заново здесь — налог
без выигрыша: тексты уже сверены с `ru.json`, вёрстка уже на брендовых токенах,
поведение уже проверено headless-прогонами прототипа.

## Решение

1. **На время W50 перенос кода из `prototypes/` в продукт разрешён.**
   Вёрстка, тексты и разбор гео переносятся дословно туда, где продукт
   расходится с вердиктом; источник переноса указывается в журнале W50
   строкой вида «из `prototypes/app.js:NNN`».
2. **Обе поверхности сразу.** Чат-флоу (`menu`, `reg-*`, `tg-router`,
   accept/notify контролёра) и SPA (5 роутов) сводятся целиком в одном пакете.
3. **Удаление без предварительного списка разрешено.** Владелец снял требование
   инвентаризации перед сносом; каждое удаление фиксируется в журнале и
   каталоге тем же коммитом, а не отдельным согласованием.
4. **Остальное заморожено.** W10, W47, W12b, W12c, W25/W27, W39 и приёмка W15
   не берутся, пока W50 не станет `готов`.
5. **После W50 п. 4 ADR-0026 возобновляется.** Прототип архивируется по п. 5
   ADR-0026 отдельным решением; новые расхождения — новыми пакетами.

## Следствия

- Цена прямого переноса — дрейф двух копий — принимается сознательно и
  закрывается сроком жизни прототипа (п. 5): после приёмки W50 эталоном
  остаётся продукт, а не мок.
- Тексты-новинки вердикта (`menu` гостя/овнера/контролёра) входят в `ru.json`
  общими ключами, а не словарём `proto.*`: словарь прототипа для отыгранного
  больше не используется (правило ADR-0031 п. 3).
- Ревью W50 сверяет продукт с прототипом построчно по местам переноса, а не
  только с SPEC.

## Альтернативы

- **Переписать всё заново по п. 4.** Отвергнуто владельцем: дольше, а
  расхождение с уже принятой вёрсткой и текстами вероятно выше, чем при
  дословном переносе.
- **Заморозить перенос кода, брать по поверхностям.** Отвергнуто: расхождения
  чата и SPA связаны (кнопки меню ↔ роуты), деление даёт промежуточные
  состояния, где чат ведёт на несуществующее.
