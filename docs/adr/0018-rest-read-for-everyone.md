# 0018. REST на чтение — всем; экспорт флоу возвращается в репозиторий

**Статус:** принято, 2026-09-13. Решение владельца проекта.

**Отменяет** [ADR-0006](0006-rest-read-only-for-review.md) целиком: ограничение
«REST только ревьюеру» снято.

**Частично отменяет** [ADR-0004](0004-catalog-instead-of-flow-export.md) — в
части запрета выгружать `flows/*.json` в репозиторий. Всё остальное в ADR-0004
остаётся в силе: каталог ведёт агент, и каталог обязан совпадать с живым
проектом.

## Контекст

Запрет на REST был конвенцией организации, а не техническим ограничением.
ADR-0006 уже пробил в нём дыру под ревьюера, потому что MCP не отдаёт
`settings.input` PIECE-шагов — URL, cron-выражения, таймзоны и порядок
аргументов `hmac-signature` иначе не проверить.

Дыра оказалась узкой не там, где надо. Свежий случай:
[Q37](../OPEN-QUESTIONS.md#q37) — у `send_text_message` и `edit_message_text`
проп `format` имеет умолчание `MarkdownV2`, и неэкранированные пользовательские
данные дают `400` от Telegram, то есть **молча непроходящее сообщение**.
Что реально стоит в `format` у построенных шагов, владельцу пакета не видно:
`ap_flow_structure` возвращает по шагу только `name`, `type`, `displayName`,
`parentName`, `relationship`, `valid`, `configStatus`. Проверено прогоном на
`reg-phone` — это не предположение.

В результате владелец пакета не может проверить собственную работу, а обязан
дождаться ревьюера, чтобы узнать, нет ли у него бага. Это не дисциплина,
а искусственный барьер: чтение ничего не ломает.

Отдельный аргумент за экспорт: с `flows/*.json` в git разница в
`settings.input` становится **видимой в диффе**. Класс дефектов, ради которого
ADR-0006 вообще написан — незаметная смена URL, таймзоны, порядка аргументов
подписи — переходит из «ревьюер сходил и посмотрел» в «видно в PR».

## Решение

1. **`GET` к REST API платформы разрешён всем ролям и без ограничения по
   эндпоинтам.** Владелец пакета, ревьюер, любой агент. Ограничение ADR-0006
   («только ревьюер, только два эндпоинта») снято.

2. **`POST` / `PATCH` / `DELETE` по-прежнему запрещены — никому.** Сборка,
   правка и публикация флоу идут только через MCP. Причины две, обе
   подтверждены историей проекта:
   - `ap_validate_flow` перед публикацией — единственная автоматическая
     проверка, которая у нас есть вместо тестов;
   - запись мимо MCP делает расхождение каталога с проектом вероятным.
     Это уже происходило: `event-wizard` был собран на инстансе мимо процесса
     (66 непроверенных шагов, включая авторизацию owner'а), а
     [Q34](../OPEN-QUESTIONS.md#q34) — ENABLED-вебхук, которого нет ни
     в каталоге, ни в репозитории.

3. **`flows/*.json` выгружаются и коммитятся в репозиторий.** Запрет ADR-0004
   на экспорт снят.

4. **У экспорта и каталога разные роли, и они не конкурируют:**

   | | `flows/*.json` | `catalog/flows/*.md` |
   | --- | --- | --- |
   | Отвечает на вопрос | **что именно настроено** | **зачем это и на чём ломается** |
   | Как появляется | выгрузкой, машинно | пишет агент |
   | Правится руками | **никогда** | всегда |
   | Точность | побайтовая | смысловая |

   Каталог **не дублирует** экспорт. Из карточек уходит перечисление инпутов
   там, где оно было механическим пересказом; остаётся назначение шага,
   зависимости и грабли, на которые шаг настроен, — карточка по-прежнему
   читается как рецепт ([CLAUDE.md](../../CLAUDE.md), «Каталог — инструкция,
   а не дневник»).

5. **Правило свежести — то же, что у каталога:** экспорт обновляется **тем же
   коммитом**, что и изменение флоу. Протухший снимок хуже отсутствующего
   ровно по той же причине, по которой это верно для каталога: по нему
   принимают решения.

6. **Ключ платформы не коммитится.** Передаётся переменной окружения и
   подставляется так, чтобы не попасть ни в вывод команды, ни в историю
   оболочки. Это правило из CLAUDE.md не меняется и распространяется теперь
   на всех, а не только на ревьюера.

7. **Проверка `settings.input` переезжает в ревью диффа.** Пункт чек-листа
   ревьюера про URL, cron, таймзоны и порядок аргументов `hmac-signature`
   больше не требует отдельного похода в REST — но требует, чтобы дифф
   экспорта был в PR. Ревьюер по-прежнему сверяет каталог с **живым** проектом:
   экспорт — это снимок, а не реальность.

## Условие, блокирующее пункт 3

**Перед первым коммитом экспорта обязательна проверка, что шаблон флоу не
содержит секретов** — [Q38](../OPEN-QUESTIONS.md#q38).

`GET /api/v1/flows/:id/template` отдаёт `settings.input` всех шагов. В наших
шагах туда подставляются `{{variables['BOT_TOKEN']}}`, `{{variables['QR_SIGNING_KEY']}}`
и `{{connections[...]}}`. Если платформа отдаёт их **ссылкой** (как написаны) —
всё чисто. Если хотя бы где-то **резолвит значение** — мы коммитим боевой
токен бота и ключ подписи QR в git, и это не откатывается удалением файла.

[ADR-0005](0005-secrets-visible-in-run-logs.md) уже признал, что секреты видны
в логах прогонов, и назвал это ценой ADR-0001. Секреты в git — другой порядок
величины: логи живут на инстансе и стираются, история репозитория — нет.

Пункт 1 (чтение) и пункт 2 действуют немедленно. Пункт 3 — только после
ответа на Q38.

## Цена

- **Описаний системы становится три, а не два:** живой проект, экспорт,
  каталог. Именно этого избегал ADR-0004, и снятие его запрета возвращает
  риск в полном объёме. Разделение ролей (п. 4) и правило свежести (п. 5) —
  смягчение, а не устранение: разойтись теперь могут любые два из трёх.

- **Дифф экспорта шумный.** В шаблоне лежат идентификаторы, версии qadam'ов
  и служебные поля, меняющиеся без смысловых изменений. Риск понятный:
  ревьюер начнёт пролистывать большие дифы, и ровно в них потеряется та
  единственная строка `format`, ради которой всё затевалось. Нужна ли
  нормализация экспорта перед коммитом — оставлено открытым
  ([Q39](../OPEN-QUESTIONS.md#q39)); отдельно оговорено, что скрипт выгрузки
  и нормализации — инструмент репозитория, а не часть продукта, и ADR-0001
  он не нарушает.

- **Искусственность снята не полностью.** Запись через REST остаётся
  запрещённой, и если проект упрётся в [#411](https://github.com/aiqadam/qadam-flow/issues/411)
  (шаги `tables`/`store`/`telegram-bot` меняются только пересозданием),
  вопрос придётся открывать заново отдельным ADR — а не решать по ходу
  «нам же разрешили REST».

## Что остаётся в силе

- **ADR-0001** целиком.
- **ADR-0004** в главном: каталог ведёт агент, каталог обязан совпадать
  с живым проектом, правило синхронизации после каждого изменения флоу
  не отменяется — к нему добавляется обновление экспорта.
- **Правило «секретов в репозитории нет»** — усиливается, см. Q38.
- **`ap_validate_flow` перед публикацией** — обязателен.

## Альтернативы

- **Снять запрет полностью, включая запись.** Отвергнуто владельцем: сборка
  мимо MCP обходит `ap_validate_flow` и делает расхождение каталога
  с проектом гораздо вероятнее. Прецеденты названы в п. 2.
- **Разрешить запись узко, как аварийный путь** (там, где MCP объективно
  не умеет). Отвергнуто: «аварийный путь» без внешнего ограничителя
  становится обычным, а критерий «MCP не умеет» определяет тот же агент,
  которому лень.
- **Оставить ADR-0006 как есть.** Отвергнуто владельцем как искусственное
  ограничение: чтение ничего не ломает, а барьер стоит ровно там, где
  владелец пакета проверяет собственную работу.
- **Разрешить чтение, но экспорт не коммитить** (сохранить ADR-0004 целиком).
  Отвергнуто владельцем: без экспорта в git `settings.input` не попадает
  в дифф, и проверка остаётся ручным походом, который каждый раз надо
  не забыть сделать.
