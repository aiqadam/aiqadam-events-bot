# 0004. Агентский каталог вместо экспорта флоу в JSON

**Статус:** принято, 2026-09-08. Уточняет [ADR-0001](0001-qadam-flow-as-carrier-stack.md).

## Контекст

ADR-0001 требует, чтобы конфигурация продакшена не существовала только в UI.
Первая формулировка этого правила была «экспортируем флоу в `flows/*.json`
и версионируем файлы».

Два обстоятельства заставили её пересмотреть.

**Первое — домашняя практика.** В `qadam-flow-project-template` (обкатано на BPM Hero)
принята модель **только MCP + UI, без REST API**, а источником правды в git служит
**агентский каталог**: Markdown-описание каждого flow и таблицы, которое агент
поддерживает по живому состоянию через `ap_flow_structure` и `ap_read_step_code`.

**Второе — что мы нашли сами.** В исходниках есть эндпоинт
`GET /api/v1/flows/:id/template` («Export flow as template»), работающий с
платформенным API-ключом. То есть выгрузка в JSON технически возможна.

## Решение

**Следуем домашней практике: каталог, а не JSON-экспорт. REST API не используем.**

- изменения флоу — только через MCP;
- проект, connections, variables — только через UI;
- git хранит `catalog/*.md`, который агент синхронизирует после каждого изменения;
- перенос `events-dev` → `events-prod` — это **пересборка через MCP по каталогу**,
  а не `apply` файла.

Найденный REST-эндпоинт остаётся неиспользованным сознательно. Записываем это здесь,
чтобы через полгода никто не счёл его «забытой возможностью» и не начал тихо
выгружать флоу мимо конвенции.

## Следствия

Хорошее:

- одна модель работы на все проекты Qadam Flow в организации — агент, знающий
  BPM Hero, работает у нас без переобучения;
- каталог читается человеком на code review; JSON флоу — нет;
- нет API-ключа с доступом ко всему проекту, который надо где-то хранить и ротировать.

Плата — называем прямо:

- **синхронизация каталога держится на дисциплине агента**, а не на `git diff`
  автоматической выгрузки. Расхождение каталога и живого проекта возможно и
  обнаруживается только чтением;
- **автоматического отката нет.** Сломали флоу — чините через MCP по каталогу,
  а не откатом коммита;
- перенос между окружениями — ручная операция агента, а не команда деплоя,
  и его результат надо проверять по чек-листу пакета работ.

Первый пункт — реальный риск, поэтому правило синхронизации вынесено в `CLAUDE.md`
как обязательное, а «каталог обновлён» входит в чек-лист готовности каждого пакета
работ в [BACKLOG.md](../BACKLOG.md).
