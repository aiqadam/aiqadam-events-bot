# 0029. Роли агентов: канон в репозитории, адаптеры по харнессам

**Статус:** принято 2026-09-16 владельцем (указание «хочу, чтобы было
harness agnostic»). **Уточняет** [0004](0004-catalog-instead-of-flow-export.md)
в части агентских инструкций и **дополняет** ритуал
[work/README](../work/README.md), не меняя его.

## Контекст

В проекте работают два агента: владелец пакета и независимый ревьюер (ритуал
взят из [work/README](../work/README.md), чек-лист — из
[REVIEW-CHECKLIST](../work/REVIEW-CHECKLIST.md)). Репозиторий используется
из разных харнессов (opencode, Claude Code), а определение субагента —
вещь харнесс-специфичная: у opencode `.opencode/agent/*.md` с блоком
`permission`, у Claude Code `.claude/agents/*.md` с `tools`, у Codex — TOML
с `sandbox_mode`. Пока роль живёт только в конфиге одного харнесса, смена
инструмента означает переписать процесс, а два конфига одной роли расходятся
молча — как расходится любой второй список одного правила.

## Решение

1. **Канон роли — обычный Markdown в репозитории**
   ([docs/agents/](../agents/README.md)): входы, протокол, границы, признак
   готовности. Без имён инструментов, моделей и путей конфигов — иначе канон
   сам становится харнесс-специфичным.
2. **Адаптер харнесса — тонкий**: только frontmatter прав и указатель на
   канон и протокол. Повторённая в адаптере процедура — дефект: адаптеров
   больше одного, и они разъедутся.
3. **Запреты закрепляются правами там, где харнесс это умеет.** Канон
   называет требование, адаптер реализует максимум возможного, а ослабленное
   закрепление (Codex — только sandbox) названо в
   [docs/agents/README](../agents/README.md), а не замалчивается.
4. **Согласованность держит детерминированная проверка**
   ([tools/check-agents.py](../../tools/check-agents.py), офлайн, pre-commit
   и CI): канон на месте, AGENTS.md ссылается на роли, адаптеры тонкие,
   у ревьюера `deny` по умолчанию и read-only allow-list MCP, имена
   MCP-серверов покрыты allow-списком, URL конфигов совпадают.
5. **AGENTS.md — канонический контекст-файл** (его нативно читают Codex,
   Cursor, Gemini CLI, opencode и другие); `CLAUDE.md` — симлинк на него,
   потому что Claude Code AGENTS.md нативно не читает. Ссылки документов
   на `CLAUDE.md` остаются рабочими: это те же байты. Импорт `@AGENTS.md`
   вместо симлинка — равнодопустимая замена (и единственная, которая переживает
   Windows-чекаут); проверка принимает обе формы.

## Следствия

- Новый харнесс = новый тонкий адаптер и строка в проверке; канон не меняется.
- Сила запретов различается по харнессам и не скрывается: где харнесс умеет
  меньше, это записано, и последний рубеж остаётся за ревью.
- **Долг:** AGENTS.md превышает 32 КиБ — лимит контекста Codex
  (`project_doc_max_bytes`). При переходе на Codex часть инструкций молча
  обрежется; разгрузка файла на короткий корень и доки по ссылкам — отдельная
  задача.
- Роли — про процесс, а не про продукт: SPEC, каталог, прототип
  ([0027](0027-prototype-as-target-reference.md)) и секреты не затрагиваются.

## Альтернативы

- **Определять роли только в конфиге одного харнесса.** Отвергнуто: привязка
  процесса к инструменту — ровно то, от чего уходим.
- **Генерация адаптеров из канона (рендерер).** Отложено: сначала проверка
  тонкости — адаптеру без процедур дрейфовать не в чем. К генерации вернуться,
  если харнессов станет больше двух или появятся поля, которые нельзя вывести
  из канона.
- **Единый внешний формат-посредник для агентов.** Отвергнуто: новый слой,
  который тоже надо вести; канон плюс указатель дешевле.
