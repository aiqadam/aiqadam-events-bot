# 0022. Mini App — React SPA на дизайн-системе бренда

**Статус:** принято, 2026-09-14. Решение владельца проекта.

**Расширяет** [ADR-0001](0001-qadam-flow-as-carrier-stack.md) — исключение Mini App
расширяется с «статические страницы без сборки» до «SPA со сборкой, без бэкенда».
**Сужает** [ADR-0017](0017-screen-not-message.md) п. 3: три разрешённые страницы
`ticket`/`scan`/`manage` становятся тремя роутами одного SPA, а не тремя
отдельными HTML-файлами. **Уточняет** [ADR-0019](0019-design-system-from-brand-repo.md)
п. 5: источник дизайн-системы — репозиторий `aiqadam/brand.aiqadam.org`, версионируется
коммитом. **Не отменяет** [ADR-0014](0014-russian-only-until-platform-i18n.md)
(русский-онли), [ADR-0020](0020-no-web-fonts-on-venue-pages.md) (без веб-шрифтов на
площадке) и [ADR-0007](0007-qr-rendered-in-miniapp.md) (QR рендерится клиентом).

## Контекст

Три страницы Mini App собраны как ванильный HTML+JS без сборки (`miniapp/ticket.html`,
`index.html`, `manage.html`): `vendor/aiqadam-brand-subset.css` 14,3 КиБ, `i18n.js`,
`qrcode.min.js`. Правило работало, пока страниц было три и каждая — один экран.

К 2026-09-14 выяснилось:

* Страницы дублируют 40% логики: тема `Telegram.WebApp.colorScheme → [data-theme]`,
  загрузка `i18n/ru.json`, `fetch` 15 с таймаутом с тремя исходами `network`/`server`/`json`
  и кнопкой «повторить» (`ticket.html:166`, `index.html:175`, `manage.html:223`). Правка
  в одном месте не доезжает в два других — уже фиксировали рассинхрон в `W30`/`W31`.
* Бренд (`brand.aiqadam.org/system.html`) — Tailwind 4 + shadcn/ui, токены OKLCH,
  доменные паттерны `EventCard`/`StatCard`/`EmptyState`. Текущий вендоринг — ручной
  срез `tokens.css` + `components.css` без версионирования и без компонентов как кода.
  Обновить бренд значит переснять срез руками.
* Следующие пакеты `W13` (списки+экспорт) и `W10` (инвайты) по `ADR-0017 п.5` — это тоже
  экраны организатора, а не сообщения. На ваниле это четвёртый и пятый дубль формы с
  валидацией, датами `Asia/Tashkent`, гео `LocationManager` и статусами `OWN-4`.

Содержать N ванильных страниц дешевле трёх, но дороже одного SPA после третьей.
Владелец разрешил снести текущую реализацию полностью, а не рефакторить её (`agreed
2026-09-14`) — цена «потерять проверенную вёрстку» меньше цены «тащить дубли».

## Решение

1. **Mini App — один React SPA, без бэкенда.** Стек: Vite + React + TypeScript,
   hash-роутер (`#/ticket?event_id=`, `#/scan?event_id=`, `#/manage`, `#/manage/:id`),
   деплой — статический `dist/` на GitHub Pages. Бэкенда для SPA нет: всё, что требует
   сервера, остаётся webhook-флоу платформы (`my-qr-api`, `checkin-api`, `manage-api`).

2. **Источник дизайн-системы — репозиторий `aiqadam/brand.aiqadam.org`.**
   `tokens.css`, `components.css`, паттерны (`EventCard` и т.д.) вендорятся копированием
   **с фиксацией коммита** в шапке (`miniapp/src/vendor/brand/*` + `BRAND_COMMIT`).
   Своих цветов, кнопок, типографики не заводим (`ADR-0019 п.2` в силе). Обновление
   бренда — отдельный коммит с переснятием, а не правка на месте.

3. **Три роута — это три бывшие страницы, не больше.** Четвёртый роут — новым ADR.
   Скоуп пакета, вводящего SPA, — `ticket`/`scan`/`manage` 1:1 по поведению (см. «Цена»),
   без `W13`/`W10` внутри. Будущие экраны организатора лягут в этот же SPA отдельными
   пакетами, но решение о них не предрешается.

4. **Снос полный.** `miniapp/*.html`, `miniapp/vendor/aiqadam-brand-subset.css`,
   `miniapp/i18n.js` (как есть), `vendor/qrcode.min.js` удаляются. Поведение
   сохраняется спекой, а не кодом: QR-плита 32px quiet zone (`ticket.html:37`),
   `qrcode.js` уровень H, размер ≤224px с `ResizeObserver` (`ticket.html:120`),
   скан-луп без закрытия между людьми (`index.html:144`), вердикт `.card` с рамкой/полосой
   тона (`index.html:45`, `manage.html:31`), даты `Asia/Tashkent → UTC` (`manage.html:254`),
   гео `LocationManager` → `navigator.geolocation` fallback (`manage.html:406`),
   статусы `OWN-4` и `ALLOWED` (`manage.html:180`), идемпотентность `newId` 12 знаков
   (`manage.html:177`), `initData` + `eventId` в каждом `POST /sync`.

5. **Ограничения сохраняются.** `ADR-0020` — веб-шрифты на `ticket`/`scan` не грузятся
   (токены `--font-*` с системными фолбэками); `ADR-0014` — русский-онли, словарь
   `i18n/ru.json` с того же Pages; палитра OKLCH без фолбэка — деградация к умолчаниям
   браузера допустима.

6. **Сборка нативная для Pages.** `pages.yml` собирает `dist/` (`npm ci && npm run build`),
   артефакт — `dist/` + `i18n/` рядом. Hash-роутер не требует `404.html` fallback и
   отдельного сервера; `browser` history не используется именно поэтому.

## Цена

* **Сборка появляется там, где её не было.** `ADR-0001` покупал отсутствие своего деплоя —
  теперь деплой статики требует `node`, `package-lock.json`, `npm audit`. Это не сервис,
  но уже не «скопировал html и готово». Workflow Pages усложняется, кэш `node_modules`
  становится частью проекта.

* **Бандл вместо страниц.** Текущие страницы 25–35 КиБ каждая + 10 КиБ CSS. SPA даже с
  code-split (`ticket`+`scan` в одном чанке, `manage` lazy) — 80–120 КиБ gzip initial.
  На площадке с плохой связью это регресс. Компенсация — чанкинг, `preconnect` к
  `app.flow.aiqadam.org`, `qrcode` lazy только на `ticket`, vendor бренда без шрифтов.
  Бюджет `initial <50 КиБ` из `ADR-0020` здесь не выполняется буквально — выполняется
  по смыслу: `ticket`/`scan` открываются до того, как догрузился `manage`.

* **Внешняя зависимость с версионированием, но всё ещё внешняя.** Бренд живёт своим
  циклом; изменение токенов поедет к нам только после переснятия, но молча устареть
  может и вендоренный срез. Цена названа в `ADR-0019` и не снимается — добавляется
  явный `BRAND_COMMIT`.

* **Потеря проверенной вёрстки.** Текущие страницы прошли 6 кругов ревью `W30`/`W31`
  (контраст 19,3:1, зона покоя 4,1 модуля, таймаут 15 с). Снос стирает эту проверку —
  SPA доказывает то же самое заново, уже на React-компонентах.

## Что остаётся в силе

* `ADR-0001` целиком, кроме расширения исключения: Qadam Flow остаётся несущим стеком,
  Code step — чистая функция, кастомный qadam не заводится, секреты в Variables.
* `ADR-0007` — QR рендерится клиентом, файл не отправляется.
* `ADR-0017` целиком, кроме п. 3: единица интерфейса — экран, `format` явно, голос
  через `docs/VOICE.md` (дельта, см. `ADR-0019 п.4`).
* `ADR-0019` — источник правды визуального языка — бренд, расхождение решается в пользу
  бренда.
* Инварианты `SPEC`: `telegram_id` единственный ключ, `consent_marketing` отдельно,
  `UTC` в хранении / `Asia/Tashkent` в показе, идемпотентность, `sig` — последние 10.

## Альтернативы

* **Оставить ваниль и модулизировать.** Отвергнуто: дубли `fetch`/`theme`/`i18n` уже
  есть, а `W13`/`W10` добавят ещё 2–3 формы. Модули без сборки не решают версионирование
  бренда и требуют половинить страницы всё равно.

* **Всё в бот-сообщения.** Отвергнуто `ADR-0017`: длинный структурированный ввод — форма,
  а не лента из 11 вопросов. Возврат к анкете ломает `ADR-0017 п.3`.

* **Next.js / SSR / отдельный хостинг.** Отвергнуто: требует бэкенда/ноды на сервере,
  ломает «GitHub Pages нативно, без сервера» и `ADR-0001`. Hash-SPA покрывает задачу
  без сервера.

* **Вендорить бренд ссылкой на `brand.aiqadam.org`.** Отвергнуто: внешний CSS без
  фиксации версии — проект ломается от чужого коммита без нашего ревью (цена `ADR-0019`).
  Копия с коммитом даёт контроль.
