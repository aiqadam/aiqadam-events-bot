# 0049. Упразднить `dedup-report`: ключи закрыли дубли, суточная диагностика не нужна

**Статус:** принято 2026-09-28 (решение владельца в чате). Упраздняет пакет
[W12b](../work/W12b-dedup-report.md) и сужает [Q42](../OPEN-QUESTIONS.md#q42);
опирается на [ADR-0047](0047-unique-keys-and-types-after-audit.md), не отменяет
[ADR-0003](0003-idempotency-without-atomicity.md)/[ADR-0011](0011-idempotency-on-atomic-primitives.md).

## Контекст

[W12b](../work/W12b-dedup-report.md) (2026-09-21) построил суточный
`dedup-report` — флоу по расписанию, который **считал** дубли строк по ключевой
паре в `registrations`, `event_staff`, `broadcast_targets` и присылал счётчики
всем строкам `staff`. Замысел: [ADR-0011](0011-idempotency-on-atomic-primitives.md)
оставлял дубли данностью (upsert — не уникальный индекс), число было неизвестно,
и без него нельзя было судить, нужна ли уборка ([Q42](../OPEN-QUESTIONS.md#q42)).

За неделю до этого решения состояние изменилось:

- **ADR-0047 (W113b, 2026-09-28) объявил уникальные ключи** на семи таблицах,
  включая `registrations(event_id, telegram_id)`. Дубль там теперь невозможен —
  сервер отвечает `RECORD_DUPLICATE_KEY`, upsert идёт через `ON CONFLICT`.
  Строка отчёта «registrations: лишних N» структурно всегда `0`.
- **`event_staff` намеренно без ключа**: revoked и active строки одной пары
  сосуществуют по дизайну ([ADR-0024](0024-staff-by-chapter-event-staff-checkin.md),
  `manage-api`), поэтому его «лишние» — в основном **штатные** повторы
  (возврат прав, повторный инвентарь), а не мусор. Метрика вводила в
  заблуждение.
- **`broadcast_targets`** — эфемерная цель одного цикла рассылки, собирается
  один раз при старте; соглашение флоу держит уникальность пары.

То есть из трёх строк отчёта две потеряли сигнал, а третья — самый узкий
случай. Цена при этом реальна: одно Telegram-сообщение в сутки владельцу и
чтение трёх таблиц целиком без `limit` (риск `LOG_SIZE_EXCEEDED` до отправки),
ради счётчика, который почти всегда ноль.

## Решение

1. **Упразднить `dedup-report` на dev**: удалить флоу (не отключать),
   зафиксировав строку `delete` в `migrations` до удаления ([ADR-0021](0021-repo-is-source-of-truth-migrations-table.md)).
   Снять ключи `dedup.*` из `i18n/{ru,uz,en}.json` и из платформенных переводов.
   Удалить карточку `catalog/flows/dedup-report.md`, экспорт `flows/dedup-report.json`
   и запись в `flows/_manifest.json`; обновить `catalog/overview.md` и ссылки,
   называвшие W12b живым.
2. **Не заменять отчёт другим фоновым флоу.** Наблюдаемость дублей держится не
   расписанием, а инвариантом: там, где пара — доменный ключ, уникальность
   обеспечена БД (ADR-0047); там, где пары нет по дизайну (`event_staff`),
   повторы ожидаемы и не являются дефектом.
3. **prod не трогается этим решением** — он замороженная копия dev
   ([ADR-0042](0042-two-environments-one-repo.md)); удаление флоу на prod —
   отдельный хотфикс в окно cutover.

## Следствия

Хорошее:

- минус суточное сообщение и минус полное чтение трёх таблиц в лог прогона;
- метрика, которую нельзя было трактовать однозначно, перестаёт существовать —
  вместо неё прямой инвариант (ключ БД).

Плата — называем прямо:

- **пропадает единственная наблюдаемость появления дублей** в таблицах без
  объявленного ключа. Если гонка когда-нибудь вернёт дубль в
  `broadcast_targets`, узнать об этом можно будет только из последствий
  (повторная отправка), а не из ночного отчёта. Признано приемлемым: таблица
  эфемерна и пишется одним циклом, а дубли и раньше схлопывались при чтении.
- Строка ADR-0047 «`dedup-report` остаётся полезной диагностикой» отражала
  состояние до этого решения и здесь **перекрыта** новым ADR, а не
  переписана задним числом.

## Альтернативы

- **Сузить до `registrations` + `broadcast_targets`** (убрать шумный
  `event_staff`) — отклонено: отчёт остаётся ежедневным сообщением ради
  счётчика, который по `registrations` гарантированно ноль, а по
  `broadcast_targets` почти всегда; оставшаяся ценность не оправдывает флоу.
- **Оставить как есть** — отклонено: ADR-0047 сделал две строки из трёх
  неинформативными, а метрику `event_staff` — вводящей в заблуждение.
- **Заменить на уборку дублей** — не рассматривается: уборка не чинит
  корректность (дубли схлопываются при чтении), а фоновое удаление строк —
  механизм с риском, который проект сознательно не заводит ([Q42](../OPEN-QUESTIONS.md#q42)).
