# 0055. Разбор ссылок Яндекс.Карт: все формы «Поделиться»

**Статус:** принято, 2026-10-05, решением владельца. Развивает
[Q55](../OPEN-QUESTIONS.md#q55)/[W42](../work/W42-event-wizard.md) (орг-ссылка
через Геокодер). Уточняет [SPEC](../SPEC.md) OWN-1. Часть пакета
[W136](../work/W136-yandex-link-formats.md).

## Контекст

Визард события принимает ссылку Яндекс.Карт и достаёт из неё точку. Сейчас
разбираются только `pt`/`ll`, `@lat,lon`, `q=lat,lon` и голая пара
(`Manage.tsx`, `parseYandexLink`), а сервер вырезает `oid` лишь из пути
`/maps/org/<slug>/<oid>` (`manage-api/step_34`). Живой пример владельца —
**новый формат «Поделиться»**:

```
https://yandex.uz/maps/10335/tashkent/?ll=69.245104%2C41.311005
  &poi[point]=69.244228%2C41.311215
  &poi[uri]=ymapsbm1://org?oid=74162995744&z=17.87
```

— не разбирается: запятые закодированы (`%2C`), точка организации — в
`poi[point]`, `oid` — в `poi[uri]`, а `oid` в пути отсутствует. Короткие
`yandex.*/maps/-/<code>` тоже не поддержаны (Q55). При этом разведка показала:
короткая ссылка отдаёт `301` с заголовком `Location`, содержащим полный URL, и
HTTP-шаг платформы этот заголовок возвращает, — то есть короткие разрешимы
сервером.

## Решение

1. **Клиент декодирует URL** (`decodeURIComponent` с фолбэком) и распознаёт
   формы: `poi[point]=<lon>,<lat>`, `pt=<lon>,<lat>`, `ll=<lon>,<lat>`,
   `@<lat>,<lon>`, `q=<lat>,<lon>`, голую пару `lat, lon` — независимо от
   кодирования `,`/`[`/`]`.

2. **Приоритет координат**: `poi[point]` > `pt` > `ll` > `@`/`q`/голая пара
   (десятичная запятая в паре допустима). `oid` — **не источник координат, а
   триггер Геокодера**: при `oid` без `poi[point]` (орг-ссылка с `?ll=…`) центр
   карты не берётся, точку и адрес отдаёт Геокодер; при `poi[point]` вместе с
   `oid` точку даёт ссылка, а Геокодер — адрес.

3. **`oid` распознаётся в двух местах**: путь `/maps/org/<slug>/<oid>` и
   `poi[uri]=ymapsbm1://org?oid=<oid>` (после декодирования). Найденный `oid`
   уходит в Геокодер (`uri=ymapsbm1://org?oid=…`), отдающий точку **и адрес**.

4. **Ссылки-адрес без координат** (`text=` / `q=<адрес>`) сервер отправляет в
   Геокодер по `geocode=<текст>` — точка из результата.

5. **Короткие `yandex.*/maps/-/<code>`** сервер разворачивает HTTP-GET без
   перехода по redirect и читает заголовок `Location`; полученный URL
   возвращается странице в поле `expanded`, которая разбирает его как обычную
   ссылку (пп. 2–4) и, если нужен Геокодер (`oid`/текст), зовёт `resolve_geo`
   ещё раз. Если разворот или Геокодер отказали — понятная подсказка
   «скопируйте координаты», ничего не теряется.

6. **Адрес** подставляется из Геокодера только там, где он вызывался (`oid` или
   текст); при координатах из ссылки адрес владелец пишет сам. Заполняется
   только пустое поле — введённое вручную не затирается.

7. **Только Яндекс.Карты** (`yandex.*/maps/…`). Google Maps и прочие — вне
   решения.

## Следствия

- **SPEC OWN-1** расширен перечнем форм ссылки.
- `manage-api` `resolve_geo` получает несколько режимов (`oid`/`text`/`short`/
  `coords`/`none`) и, для коротких, дополнительный HTTP-шаг разворота; точка
  входа остаётся одна — действие `resolve_geo`, права те же (staff того же
  чаптера, `initData`), произвольные URL через флоу не ходят.
- Расход квоты Геокодера растёт (текст и короткие — дополнительные вызовы);
  условия и цена свободного тарифа остаются принятыми в Q55.
- Короткие ссылки теперь зависят от поведения `Location` у Яндекса; при его
  изменении деградация — та же подсказка.
- Клиентский разбор остаётся локальным и бесплатным; сеть — только когда
  координат в ссылке нет.
