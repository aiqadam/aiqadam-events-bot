# 0042. Две среды в одном репозитории: `events-dev` — канон, `events-prod` — замороженная копия

**Статус:** принято, 2026-09-26. Уточняет [ADR-0004](0004-catalog-instead-of-flow-export.md)
и [ADR-0021](0021-repo-is-source-of-truth-migrations-table.md); развивает решение Q14.

## Контекст

До сих пор репозиторий описывал **одну** среду — `events-dev`:
`catalog/*` и `flows/*.json` сняты с dev, `tools/export-flows.sh` и
`tools/check-migrations.py` знают один `projectId`, AGENTS.md заводит один
MCP-сервер. [ARCHITECTURE.md](../ARCHITECTURE.md) при этом говорил о двух
проектах внутри одного инстанса.

2026-09-26 владелец поднял второе окружение на **отдельном инстансе**
(`app-prod.flow.aiqadam.org`) как **копию dev на уровне базы** (восстановление
дампа и замена telegram-connection на `Events-Prod`). Следствия копии важно
назвать прямо:

- у dev и prod **совпадают `flowId`, id таблиц/полей и переменных** и даже
  секунды их создания — по данным среды не отличить;
- **единственный различитель среды — префикс MCP-сервера**
  (`app-flow-events-dev` / `app-flow-events-prod`);
- предпосылка Q14 («у dev и prod разные `flowId`»), на которой строилось
  разделение Mini App, временно не выполняется;
- каталог и экспорт описывают dev и молчат о prod.

Решения владельца (2026-09-26): **prod остаётся «as is»** — замороженной
копией, без пересборки по каталогу; **dev очищается и пересобирается** из
репозитория. Копия — разовый bootstrap боевого окружения, а не отмена
ADR-0004 для дальнейшей жизни prod.

## Решение

1. **Две среды, два инстанса, один репозиторий.** `events-dev` —
   `app.flow.aiqadam.org` (MCP `app-flow-events-dev`), `events-prod` —
   `app-prod.flow.aiqadam.org` (MCP `app-flow-events-prod`). Среда —
   перворазрядное свойство каждой операции: **каждое изменяющее MCP-действие
   называет среду явно**; чтения по умолчанию — dev, prod читается только
   когда прод явно проверяется.

2. **prod — замороженная копия.** Его структура и id не меняются, пока он
   таков; допускаются только осознанные хотфиксы (сначала dev, затем перенос),
   в окно cutover. Пересборка prod по каталогу — путь ADR-0004 — отложена и
   станет предметом отдельного ADR, когда prod перестанет быть копией.

3. **Канон — dev.** Вся разработка идёт в dev; `catalog/*` и `flows/*.json`
   описывают именно dev ([ADR-0021](0021-repo-is-source-of-truth-migrations-table.md)).

4. **Различия сред вынесены из карточек флоу.** Карточка `catalog/flows/*.md`
   описывает **логическую модель** (шаги, зависимости, грабли) — она у сред
   общая, дублировать 30+ карточек не нужно. Всё, что у сред разное, живёт в
   [`catalog/environments.md`](../../catalog/environments.md): инстанс, project
   id, MCP-сервер, `externalId` connection'ов, имена и отличия переменных, бот,
   адрес Mini App и **карта id dev↔prod** (таблицы, поля, флоу). Пока id
   совпадают, карта это фиксирует; при расхождении — обновляется.

5. **`migrations` — у каждого инстанса своя.** Сверка и журналы называют среду;
   `tools/check-migrations.py` выбирает среду переменными окружения
   (`QADAM_BASE_URL`/`QADAM_PROJECT_ID`); явный ключ `--env` — возможное уточнение позже.

6. **Mini App — один исходник, две сборки и два деплоя** (Q14). Адрес API и
   карта webhook-`flowId` подставляются на сборке (`VITE_*`), не в рантайме;
   у каждого бота в BotFather свой Mini App URL.

7. **Совпадение id — не гарантия, а текущее состояние.** Очистка и пересборка
   dev меняет id dev; каталог (`catalog/environments.md`) и dev-сборка Mini App
   обновляются **тем же пакетом работ**, что и пересборка. Полагаться на «id
   одинаковые» нельзя нигде.

## Следствия

Хорошее:

- у среды один адрес в документации и одна точка правды (`catalog/environments.md`),
  а не «угадай по MCP-префиксу»;
- карточки флоу не размножаются по средам — расходятся только дельты;
- prod можно трогать осознанно и редко, dev — свободно ломать и пересобирать.

Плата — называем прямо:

- **одинаковые id делают ошибку «не в ту среду» почти бесшумной**: правило
  «вызов называет среду» держится дисциплиной и ревью, офлайн-проверкой его
  не поймать (MCP-вызов необратим и не виден в git);
- prod, оставленный копией, несёт историю dev в `migrations` и не проверен
  пересборкой — расхождение с каталогом там возможно и ловится только чтением;
- пока prod — копия с id dev, Q14 «свой `flowId` на сборку» не работает как
  задумано: Mini App сред различаются **хостом**, а id общие. Это временно и
  должно быть снято, когда id разойдутся.
