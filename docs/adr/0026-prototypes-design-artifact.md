# 0026. Прототипы — артефакт дизайна, не поверхность продукта

**Статус:** принято, 2026-09-15, владельцем (черновик пакета
[W41](../BACKLOG.md#w41-ui-прототипы-end-to-end-чат-бота-и-mini-app)).
**Расширяет** ADR-0001 (0 кода) в части «что считается продуктом» и
**уточняет** [ADR-0017](0017-screen-not-message.md) п. 3 и
[ADR-0022](0022-miniapp-react-spa.md): прототипы не являются страницей
Mini App и не меняют число её роутов.

## Контекст

Владелец заказал UI-прототипы end-to-end для Mini App и Telegram-бот UX,
«чтобы визуально понимать — то или нет» ([W41](../BACKLOG.md#w41-ui-прототипы-end-to-end-чат-бота-и-mini-app)).
Прототип показывает построенные экраны v0.1 и предложения v0.2 кликабельными,
до того как под них дописываются флоу и страницы.

Из этого возникает вопрос границы: прототип — это HTML, который открывается по
URL и выглядит как Mini App. Без явного решения он незаметно становится
«пятой страницей» — расширением ADR-0017 п. 3, — или вторым, параллельным
SPA, которое живёт своей жизнью. Оба исхода ломают проект: первое снимает
ограничение «четвёртая страница — только новым ADR», второе создаёт второй
источник правды по UI рядом с `miniapp/`.

## Решение

Прототипы — **артефакт дизайна с конечным сроком жизни**, а не поверхность
продукта. Конкретно:

1. **`prototypes/` не является страницей Mini App.** ADR-0017 п. 3 и ADR-0022
   не расширяются; роутов у SPA остаётся три (четвёртый, `#/events`, — только
   по ADR-0023). Прототип не имеет роута внутри `miniapp/`.

2. **`prototypes/` не входит в бандл SPA.** Сборка Mini App (`npm run build`)
   прототип не трогает. На деплое `pages.yml` кладёт его рядом с корнем Mini
   App (`{{MINIAPP_URL}}prototypes/`), отдельным путём, из вендоренной копии
   бренда, а не из SPA.

3. **Прототип не линкуется из бота, флоу и SPA.** Ни одной ссылки на
   `prototypes/` в карточках, кнопках и роутах. Проверяется grep'ом на ревью.

4. **Код продукта из прототипа не копируется.** Перенос экрана в продукт —
   отдельный пакет BACKLOG; прототип — доказательство замысла, не реализация.
   Это держит «0 кода»: прототип не становится тихой второй реализацией.

5. **После вердикта прототип архивируется или удаляется отдельным решением.**
   Он не живёт «вечно рядом с продуктом»: второй UI-артефакт дрейфует от
   продукта по мере правок SPA, и это названная цена, а не баг.

## Следствия

- **Второй UI-артефакт в репозитории на время пакета.** Принимается:
  это дизайн-инструмент с конечным сроком жизни, не вторая реализация.
- **Ручной повтор вёрстки.** Изменение продуктовой страницы не приезжает
  в мок само; прототип обновляется под конкретную задачу, а не «всегда свежий».
- **Время владельца.** Проход прототипа и вердикт по каждому экрану — шаг
  человека; без него пакет остаётся `на проверке`.
- **`catalog/` не меняется:** пакет не трогает инстанс — отступление от
  общего правила каталога ([ADR-0004](0004-catalog-instead-of-flow-export.md))
  названо в чек-листе пакета.

## Альтернативы

- **Прототип как четвёртая/пятая страница SPA.** Отвергнуто: снимает границу
  ADR-0017 п. 3 без нового решения о роуте, втягивает прототип в продуктовый
  бандл и делает его «настоящим», хотя он — временный.
- **Отдельный деплой вне GitHub Pages.** Отвергнуто: у проекта один хостинг
  (Pages, шаг 0.4); отдельный путь стоит дешевле, чем второй деплой.
