# 0031. Прототип покрывает расширенный v0.1

**Статус:** предложен 2026-09-18 — на принятие владельцем. **Уточняет**
[ADR-0027](0027-prototype-as-target-reference.md) (прототип — целевой эталон):
фиксирует, что именно эталон покрывает после расширения v0.1 решением
владельца 2026-09-18 (W10, W47, W12b, W12c, W25/W27 возвращены в v0.1, W39 —
в v0.2). Сам ADR-0027 не правится задним числом.

## Контекст

После расширения v0.1 за пределы прототипа возник вопрос, закрывает ли эталон
новые пакеты. Разбор W49 показал: рисовать почти нечего — UI расширенного v0.1
в прототипе уже был (W10: создание инвайта + accept ok/invalid/used/expired;
W42–W45, W44: визард, каталог, регистрация на месте, staff-поиск, фидбек;
W48: `viewport-fit=cover` и safe-area). Реальная гниль была в другом месте:
38 ключей `protoDict`, отыгранных продуктом (тексты W42–W45 сгенерированы из
`i18n/ru.json`), — детерминированный чек `prototypes/check.mjs` покраснел
(exit 1). Плюс протухшие пометки «предложение / черновик ADR-0028» после
принятия ADR-0028. W49 всё это вычистил: чек зелёный (exit 0, ноль
предупреждений), живой рендер снят (10 экранов, обе темы, ноль ошибок консоли).

## Решение

1. **Прототип — эталон UI всего v0.1, кроме явно перечисленного ниже.**
   Матрица покрытия (сценарии чата + экраны Mini App): гость (регистрация,
   согласия, билет, напоминания, послесловие-благодарность, отмена, состояния);
   овнер (меню, визард 4 шага с гео и ёмкостью, публикация, правка, участники
   и экспорт, рассылка полным циклом, staff-поиск, создание инвайта);
   контролёр (приём инвайта ok/invalid/used/expired, сканер 4 исхода, луп);
   каталог (3 таба, регистрация на месте, «Мои билеты» первым); фидбек
   (форма + успех — приняты, не предложение).
2. **Явные непокрытия — эталоном для них служит текст BACKLOG, а не экраны:**
   поведение W47 (BackButton, haptics, closing confirmation, vertical swipes —
   рантайм WebView, в статическом моке не демонстрируется); сообщение W12b
   (опс владельцу проекта, вне трёх ролевых сценариев); W12c, W25/W27, хвосты
   W46 (Q31/Q32/Q14) — невидимое поведение. W39 (афиша) отсутствует по праву —
   v0.2.
3. **Тексты прототипа — из `i18n/ru.json`; словарь прототипа — только ещё не
   написанное** (п. 6 ADR-0027, enforced чекером §5). Отыгранный ключ из
   `protoDict` удаляется, использования переводятся на настоящий ключ.
4. **`prototypes/check.mjs` — ворота эталона:** exit 0 с нулём предупреждений
   обязателен; сломанный чек — это протухший эталон, чинится пакетом, а не
   игнором.

## Следствия

- Пакеты W10, W47, W12b, W12c, W25/W27 берутся по BACKLOG+SPEC; сверка
  «продукт ↔ прототип» для них — только там, где есть экран (W10).
- Живой рендер прототипа — сборка как на Pages (`prototypes/` + вендор
  бренда + `i18n/`); скриншоты — глазами, чекер — воротами.
- Обновлять прототип под каждую правку SPA по-прежнему не нужно (ADR-0027):
  ворота ловят дрейф текстов и роутов, остальное — вердиктом.

## Альтернативы

- **Дорисовать W12b и W47 в прототип.** Отвергнуто: сообщение-опс не
  принадлежит ни одной ролевой истории, поведения WebView статический мок
  не демонстрирует — рисунок был бы картинкой ради картинки, а эталоном
  остался бы текст.
- **Не фиксировать покрытие, оставить «прототип = эталон» декларацией.**
  Отвергнуто: без матрицы и списка непокрытий следующий спор «а это в
  эталоне?» решается памятью, а не документом.
