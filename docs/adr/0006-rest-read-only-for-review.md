# ADR-0006. REST API — только ревьюеру и только на чтение того, чего не отдаёт MCP

- **Дата:** 2026-09-08
- **Статус:** принято
- **Контекст:** [ADR-0004](0004-catalog-instead-of-flow-export.md) (не отменяется),
  [Q7](../OPEN-QUESTIONS.md#q7)

## Проблема

ADR-0004 запретил REST API целиком: строим и меняем флоу через MCP, окружение —
через UI, источник правды в git — агентский каталог `catalog/*.md`. Решение
работает, и мы его не отменяем.

Но за пакетами W2 и W3 обнаружилась дыра, которую каталог не лечит. **MCP не
отдаёт входы PIECE-шагов:** `ap_read_step_code` работает только для CODE-шагов,
`ap_get_run` — только для выводов, `ap_flow_structure` показывает имена и типы,
но не `settings.input`. Проверить нельзя ни одного из этих утверждений:

- какие URL стоят в `i18n-sync` — ветка или `main`;
- какое cron-выражение и таймзона у триггера;
- в каком порядке переданы аргументы `hmac-signature` в `fn-verify-init-data`;
- какие фильтры реально стоят в `tables-find-records`.

Каждое — место, где ошибка тихая. Обратная ориентация HMAC прошла бы все восемь
проверок владельца W2 одинаково: он проверял согласованность цепочки с самой
собой. Неверный cron не даёт ошибки — он просто не срабатывает.

Ревьюеры W2 и W3 упёрлись в это **независимо**, каждый записал «проверить не
смог», и оба нашли обходные пути: различающий прогон, который при неверной
конфигурации дал бы другой результат, и независимый пересчёт HMAC через
`openssl`. Приёмы рабочие, но это доказательства второго порядка, и придумывать
их заново придётся в каждом пакете.

Цена очевидна: юнит-тестов в проекте нет — это плата за «0 кода» ([ADR-0001](0001-qadam-flow-as-carrier-stack.md)).
Ревью с чистым контекстом — единственная замена тестам, которая у нас есть.
Ревью с завязанными глазами в части конфигурации шагов — замена наполовину.

## Решение

**Ревьюеру разрешён REST API на чтение — и только для того, чего не отдаёт MCP.**

Разрешено:

- `GET /api/v1/flows/<flowId>/template?projectId=<id>` — отдаёт `settings.input`
  каждого шага целиком, включая PIECE-шаги и триггер;
- `GET /api/v1/flows?projectId=<id>` — список флоу со статусами.

Запрещено — по-прежнему и всем, включая ревьюера:

- любые `POST` / `PATCH` / `DELETE`: строить и менять флоу только через MCP;
- REST владельцу пакета: сборка, отладка и снятие структуры для каталога — MCP;
- REST как источник правды в git: выгружать `flows/*.json` в репозиторий нельзя,
  каталог остаётся единственным описанием системы (в этом ADR-0004 не тронут);
- коммитить API-ключ. Ключ передаётся ревьюеру вне репозитория, через
  переменную окружения; в командах подставляется так, чтобы не попасть ни в
  вывод, ни в историю.

## Почему именно так

Асимметрия «владельцу нельзя, ревьюеру можно» выглядит странно, но она и есть
смысл решения. ADR-0004 защищает от того, чтобы проект незаметно уехал в
кодовую разработку: скрипт выгрузки → скрипт заливки → свой деплой. Чтение
конфигурации проверяющим такого хода не открывает: у ревьюера нет права ничего
менять — ни через REST, ни через MCP.

Дополнительный аргумент — экспорт не содержит секретов. Bot token присутствует в
нём **ссылкой на connection** (`{{connections['<id>']}}`), а не значением;
проверено на `fn-verify-init-data`. Это отличает его от логов прогонов, где
производный секретный ключ Telegram лежит открытым текстом ([ADR-0005](0005-secrets-in-run-logs.md)).

## Цена

1. **Конвенция «только MCP + UI» перестала быть однострочной.** Появилось
   исключение, а исключения имеют свойство расширяться. Поэтому граница
   проведена по роли и методу, а не по удобству: read-only, ревьюер, и только то,
   чего MCP не отдаёт. «Мне так быстрее» — не основание.
2. **Ревьюеру нужен платформенный API-ключ.** Это второй секрет в обороте
   помимо bot token и `QR_SIGNING_KEY`, и он не привязан к проекту — его область
   шире, чем `events-dev`. Ключ не коммитится; при подозрении на утечку
   отзывается в UI.
3. **Экспорт может разойтись с draft.** Он отдаёт опубликованную версию, а
   владелец мог правиться после публикации. Ревьюер сверяет `publishedVersionId`
   и не считает экспорт снимком того, что видит владелец в редакторе.

## Что это меняет в документах

- `CLAUDE.md` — раздел «Модель работы» и Safety rules: запрет REST переформулирован
  с исключением;
- [REVIEW-CHECKLIST.md](../work/REVIEW-CHECKLIST.md) — новый блок «Конфигурация
  PIECE-шагов», обязательный для пакетов с HTTP-шагами, cron-триггерами и
  криптографией;
- [Q7](../OPEN-QUESTIONS.md#q7) — слепое пятно ревью закрыто этим ADR.

## Альтернативы, которые отвергли

- **Оставить как есть.** Отвергнуто: три независимых упора в одно ограничение за
  два пакета — это не случайность, а системная слепота ревью. В W8, где стоит
  STF-2, цена ошибки выше всего.
- **Доработать MCP-сервер.** Правильно по существу, но это чужой репозиторий и
  чужой релизный цикл; ждать его — блокировать W4+.
- **Разрешить REST всем и на чтение.** Отвергнуто: владелец пакета получил бы
  соблазн снимать структуру для каталога экспортом, и каталог из утверждения
  агента превратился бы в сгенерированный файл — ровно то, от чего отказались в
  ADR-0004.
