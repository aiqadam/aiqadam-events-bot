# 0030. Инструмент платформы — прежде своего; перечни — примеры, а не предел

**Статус:** принято 2026-09-16 владельцем. **Уточняет**
[0001](0001-qadam-flow-as-carrier-stack.md) в части «допустимого
инструментария»; запреты 0001 (нет своего сервиса, БД, деплоя, кастомного
qadam'а) остаются в силе без изменений.

## Контекст

[0001](0001-qadam-flow-as-carrier-stack.md) перечисляет инструментарий
списком: флоу, Code steps, core-qadam'ы, `community/telegram-bot`. Форма
списка читается как закрытый allowlist, хотя платформа даёт больше готового:
core-qadam'ы и pieces сообщества шире перечня, а используемый
`telegram-bot` — как раз community-piece, а не core. Владелец зафиксировал
обратный порядок: **прежде чем изобретать, всегда стараться использовать
инструменты платформы**; любой перечень — примеры, а не предел.

Цена ошибки в другую сторону — свой код там, где у платформы есть готовый
инструмент: он дороже, хуже поддерживается и обходит ровно ту ценность, ради
которой выбран Qadam Flow ([0001](0001-qadam-flow-as-carrier-stack.md)).

## Решение

1. **Порядок выбора инструмента:** готовый qadam/piece платформы → Code step
   как чистая функция → вопрос владельцу проекта. «Написать небольшой сервис»
   не входит в этот ряд ни на каком месте (0001).
2. **Перечни инструментов в 0001 и AGENTS.md — примеры, а не исчерпывающий
   allowlist.** Готовый qadam платформы (core или community) допустим, если
   решает задачу и проходит обычные проверки: connection через UI, секретов
   нет, инварианты проекта (STF-2, DAT-1, OWN-3, IDM, PAR) соблюдены.
3. **Перед сборкой — поиск по платформе:** `ap_research_pieces` (действия
   и триггеры), `ap_get_piece_props` (поля и типы). Выбор инструмента виден
   в журнале пакета и каталоге; «готового не было — написал Code step» —
   утверждение, которое проверяет ревью.
4. **Запреты 0001 не меняются:** кастомный qadam в `packages/qadams/custom/`,
   свой бот-процесс, свой API, своя БД, свой деплой не заводятся. Code step —
   только чистая функция: ни сетевых вызовов, ни записи в БД внутри.

## Следствия

- Инструментов становится больше, чем в перечне; появляется риск взять
  community-piece с чужими багами или неполной документацией. Лечится тем же,
  чем всё остальное: чек-листом пакета и различающими прогонами, а не
  запретом на готовое.
- Обновление платформы может менять поведение pieces — это общая цена
  зависимости от площадки, учитывается при выборе.
- «0 кода» остаётся целью; меняется порядок её достижения: сначала поиск,
  потом код.

## Альтернативы

- **Оставить закрытый перечень («допустимый инструментарий»).** Отвергнуто:
  он не описывает реальность (community-piece уже используется) и толкает
  изобретать то, что на платформе есть.
- **Разрешить кастомные qadam'ы как «ещё один инструмент».** Отвергнуто:
  это форк платформы со своим релизным циклом — запрет 0001 остаётся.
