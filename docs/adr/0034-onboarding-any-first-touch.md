# 0034. Онбординг — на первое касание бота вообще, не только на первый диплинк

**Статус:** принят 2026-09-20 владельцем (решение по прямому запросу в чате,
без предварительного пакета BACKLOG). Расширяет
[ADR-0032](0032-onboarding-first-touch-profile.md), не отменяет его: порядок
шагов онбординга (согласие → эвристика имени → работа → город → «Всё
верно?»), эвристика подозрительного имени и разделение
`finish`/`finish_lite` остаются как есть.

## Контекст

ADR-0032 запустил онбординг C только из `reg-start` — то есть только когда
гость переходит по диплинку конкретного события (`/start e<eventId>-<utm>`).
Голый `/start` (первое сообщение боту без диплинка) уходил в `menu`
(W34) без единого вопроса о профиле — гость мог годами пользоваться ботом
через меню и открытый каталог `#/events`, ни разу не пройдя онбординг, если
ни разу не пришёл по прямой ссылке на событие.

Формулировка ADR-0032 («первое касание») была двусмысленной: в SPEC (PAR-8)
и в реализации она читалась как «первое касание *регистрации*», а не
«первое касание *бота*». Владелец уточнил это прямо: онбординг обязан
запускаться на первое обращение к боту вообще, независимо от диплинка, и
одинаково для всех ролей (гость, staff, owner) — своя роль не освобождает
от заполнения профиля.

## Решение

1. **Триггер онбординга — первое `/start` вообще**, не только `/start
   e<id>-<utm>`. Гейт — `users.profile_completed_at`: пусто → онбординг,
   заполнено → обычный путь (для `/start` без диплинка это прежнее меню;
   для диплинка события — прежняя ветка `register` из ADR-0032).
2. **Одна проверка на все роли.** `menu` (точка входа для голого `/start`)
   гейтит на профиль ДО чтения ролей (staff/owner) — свой чаптер, права
   контролёра и кнопка «Панель администратора» проверяются и показываются
   только после того, как профиль заполнен. Первое сообщение новому
   овнеру или контролёру — тот же экран, что и гостю.
3. **Финал без события.** Онбординг без диплинка (`eventId` пуст) после
   «Всё верно» **не создаёт регистрацию** (создавать её не на что) — пишет
   только профиль и оба согласия (PAR-1/PAR-2, то же место в коде, что и с
   событием). Финальная карточка — «Профиль сохранён» вместо «Вы
   зарегистрированы», с кнопкой, открывающей каталог `#/events` в Mini App,
   вместо кнопки билета.
4. **Онбординг с диплинком — без изменений.** Если первое касание всё же
   пришло по диплинку события, ведёт себя как в ADR-0032: заканчивается
   реальной регистрацией на это событие, кнопка — билет, а не каталог.

## Следствия

- `menu` теряет статус «простого меню-хаба» (W34): перед показом меню
  добавляется чтение `users.profile_completed_at` и ветвление. Кнопки
  staff/owner не меняются — только откладываются до заполненного профиля.
- `reg-profile` получает третий исход завершения (`finish` с событием,
  `finish_lite` — повтор, и теперь `finish` без события) — без события не
  пишет `registrations`, только `users`. Диалог (вопросы, эвристика имени)
  общий для обоих случаев с событием и без — различается только последний
  шаг записи и текст финальной карточки.
- `reg-consent-mkt` (хвост «присылать анонсы?») получает второй вариант
  финального сообщения — без билета, с кнопкой каталога — по тому же
  признаку (`eventId` пуст в черновике сессии).
- **Одноразовость и в этом случае держится `profile_completed_at`**: как
  только он проставлен (с событием или без), второе и последующие `/start`
  — что голые, что по диплинку — не переспрашивают профиль (ADR-0032 п.1).

## Альтернативы

- **Просто список ближайших событий текстом в чате** после «Всё верно» без
  события — отвергнуто: список живёт в Mini App (ADR-0015 «экран, не
  сообщение»), дублировать его текстом в чат — заводить второй источник
  правды по тому же списку, который уже есть в `#/events`.
- **Отдельная кнопка «Заполнить профиль» в меню** вместо принудительного
  онбординга на первом касании — отвергнуто владельцем: премьера
  добровольного заполнения статистически не происходит (обычная проблема
  необязательных профилей), а поимённое участие — требование, а не опция
  (тот же аргумент, что и в ADR-0032).
