`event-wizard-*` на третью страницу Mini App `miniapp/manage.html` с одним

## Чек-лист готовности

      доказано **различающим** прогоном: не-владелец → отказ, владелец → успех
      на одном и том же входе (пп. 2–3), и на входе «вся таблица» (п. 11);

      `notify-on-change`, с «было → стало»; правка прочих полей — молча (пп. 5–6);
- [x] пользовательские данные на странице вставляются через `textContent`,
      в чат уходят без `parse_mode` (`format: None` во всех трёх отправках);
- [x] решение по шрифтам `manage` записано числом (ADR-0020 п. 3) — журнал, 2026-09-14;
- [x] своих цветов, кнопок и типографики нет — `grep` из чек-листа п. 3a молчит

- [~] гео решено внутри страницы (координаты руками + `LocationManager`/`geolocation`);
      **фото — вынесено владельцу явным вопросом [Q46](../OPEN-QUESTIONS.md#q46)**,
      не урезано молча: форма поле не трогает, афиша из визарда переживает правку;
- [x] долг Mini App из круга 7 W30 (пп. 2 и 4): отказ на `ticket` — рамкой/полосой,
      а не цветом текста; у «Загрузка…» есть таймаут и «повторить», не-JSON

- [x] независимое ревью, вердикт «замечаний нет» — круг 4 (пакет) и круг 6

- [x] `catalog/` совпадает с живым проектом — утверждается владельцем,

## Журнал

- **2026-09-14** — **Шрифты `manage`: не грузим.** 444 КиБ (`cyrillic`+`latin`
  трёх семейств) против ~35 КиБ всего, что страница качает; организатор тоже
  на телефоне, а «два режима типографики внутри одной Mini App» ADR-0020
  назвал ценой — платить её ради формы незачем. Токены `--font-*` с
  системными фолбэками, как на `ticket`/`scan`.
- **2026-09-14** — **Вход в форму — временная команда `/manage [<id>]`**, а не
  `/newevent`/`/editevent`. Пакет требует, чтобы `event-wizard-*` жили
  параллельно до приёмки; перевод их команд на `manage-open` сделал бы визард
  недостижимым до вердикта. Переключение команд — в шаге вывода визарда.
- **2026-09-14** — **Фото — точка остановки, [Q46](../OPEN-QUESTIONS.md#q46).**
  Mini App не даёт `file_id`; честного решения внутри страницы нет (нужно
  хранилище или multipart через `http` — оба вне ADR-0001). Форма поле не
  трогает, вопрос владельцу с рекомендацией (отдельное касание в чате).
- **2026-09-14** — **Гео — внутри страницы**: `lat`/`lon` руками +
  `Telegram.WebApp.LocationManager` (Bot API 8.0) с фолбэком
  `navigator.geolocation`. Проверено в headless только с заглушкой; живой
  `LocationManager` не проверялся.
- **2026-09-14** — **«Respond and Continue» у `return_response`** — первое
  применение в проекте: страница получает `200` сразу после upsert'а, рассылка
  уведомлений и подтверждение владельцу идут после. Подтверждено прогоном
  `omFLv7dN7rTZbtXEA0jMS`: `step_12` (5 мс) стоит до `step_15` (430 мс).
- **2026-09-14** — **Ветки ROUTER'а не сходятся**, поэтому `return_response`
  стоит в каждой из трёх веток `step_8` отдельно, а все тела ответов имеют
  один набор ключей — иначе шаблон `{{step_7['output'].event}}` в ветке
  ошибки не резолвится.
- **2026-09-14** — **`ap_build_flow` с ROUTER создаёт пустую «Branch 1»** без
  условий; `ap_add_branch` встаёт за ней. Убрал пустую `ap_delete_branch`,
  индексы сдвинулись — проверять `ap_flow_structure` после каждого шага.
- **2026-09-14** — **Валидный `initData` лежит в логах прогонов** (`my-qr-api`
  `ic1r7lfWxth0Q1frqYDqX`) и годен 24 ч. Это позволило прогнать различающий
  тест без живого WebView, но это же значит: читающий прогоны может 24 ч
  действовать от имени пользователя во всех трёх webhook-флоу. Записано в
  карточку `manage-api`; решение (сокращать окно? резать `initData` в логе?)
  — не этого пакета, кандидат в OPEN-QUESTIONS/SECURITY.
- **2026-09-14** — **Ивент `emtzwtmr32apl` (13 символов) в форму не
  открывается** — `id` длиннее slug'а `fn-parse-start`, у него и deep link не
  работает. Данные старого визарда; форма правило не смягчает.
- **2026-09-14** — **На тестовый ивент зарегистрировались живые люди**
  (`8255904812` по ссылке из подтверждения и `738335969` — третья строка в
  `registrations`). Ивент реальный и опубликованный; при удалении его надо
  сперва отменить формой (уведомление уйдёт двоим) — см. «Хвосты».
- **2026-09-14** — **Экспорт `flows/` не снят**: `QADAM_API_KEY` в окружении
  агента нет, Keychain недоступен (Linux). `tools/export-flows.sh` и
  `check-texts.py` прогнать не смог; тексты сверены руками — все `texts`
  входов сгенерированы скриптом из `i18n/ru.json`, не набраны.
- **2026-09-14** — **Круг 1 ревью: пять «важно» исправлены** (переходы статуса
  по OWN-4 и `finished`, ключ ошибки описания, различающий прогон на всей
  таблице, — экспорт остаётся блокером), из «на будущее» закрыты 7, 8, 10,
  11, 12. Идемпотентность создания — через `newId` со страницы: цена —
  `id` теперь выбирает клиент (в пределах slug'а), а сервер проверяет, что он
  не занят чужой записью.
- **2026-09-14** — **`ap_test_flow` может выполнить прогон с сохранённым
  sample-входом вместо `triggerTestData`** (наблюдение ревьюера, прогон
  `jXsJUpOnf1ETZaNBCm8kr`: невалидный `initData` в аргументе — а прогон
  прошёл ветку `valid` с прежним телом и сделал `save`). Следствие: у флоу с
  побочными эффектами негативные проверки делать `curl`'ом на опубликованный
  `/sync`, а `ap_test_flow` — только когда тело безвредно. Кандидат в
  Gotchas CLAUDE.md.
- **2026-09-14** — **Экспорт через MCP и таблица `migrations` — решение владельца**
  («источник правды — репозиторий; хочешь доказывать синхронность — заведи
  `migrations` и записывай всё»). Оформлено [ADR-0021](../adr/0021-repo-is-source-of-truth-migrations-table.md),
  Q44 дополнен. Снимок снят `tools/export-flow-mcp.py` из сырых ответов
  `ap_export_flow` (сохранены субагентом в scratchpad). Замечено: MCP-снимок
  вычищает `auth` и пустые строки `exampleData` — записано в flows/README.
  Таблица `migrations` создана (`NCZNGuWh6PFs1JZXRPNTE`), в неё внесены записи
  о всех изменениях пакета с хэшами коммитов.
- **2026-09-14** — **Урок процесса**: временный флоу-доказательство
  (`tmp-w31-decide-whole-table`) удалён до вердикта ревью — ревьюеру круга 2

### Замечания
1. **важно** Форма допускает переходы статуса вне OWN-4 (`draft → published →
   cancelled | finished`): `published → draft` (снятие публикации при живых
   регистрациях), `cancelled → published`, `cancelled → draft` — и ни один
   не назван ни в ADR, ни в OPEN-QUESTIONS; `cancelled_at` при
   «воскрешении» очистить нечем (Q30), запись останется с `status=published`
   и заполненным `cancelled_at` — `manage-api/step_7` (`STATUSES`,
   `wasLive`), `miniapp/manage.html` (радио статуса без ограничений) —
   ТЗ не переписывается по ходу: либо форма запрещает обратные переходы,
   либо решение фиксируется отдельно и явно.
   - *Исправлено* (2026-09-14): переходы статуса — ровно OWN-4, таблица
     `ALLOWED` в `step_7` и та же на странице (радио показываются только для
