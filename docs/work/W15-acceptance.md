## Журнал

- **2026-09-18** — пакет взят. Решение владельца: dev-часть сначала,
  `events-prod` — после того как владелец заведёт бота и проект (Wave 0, 0.6).
- **2026-09-18** — `check-migrations.py` (пункт 0 чек-листа) нашёл 18
  расхождений — все в исторических строках W12/W45/W46, не в живом
  проекте. Причины и правки:
  - **w12-02, w12-04** (`disable`) — у `version_id` было значение вместо `-`
    (правило C: `version_id` непустой только у `publish`). Поле обнулено.
  - **w12-06, w12-07** — записаны с `action: enable`, которого нет в схеме
    (`create`/`update`/`publish`/`disable`/`delete`). Переведены в
    `action: update`, `version_id: -`; текст note не менялся — схема не
    различает enable/disable отдельным значением, публикуемая версия флоу
    не менялась.
  - **`tmp-w12-item-probe`** — DRAFT-флоу создан строкой `w12-05`, удалён
    (подтверждено `ap_list_flows`: 0 совпадений), но строки `delete` не
    было — сам журнал W12 уже фиксировал этот пробел как «не критично».
    Добавлена `2026-09-17-w12-11` (action `delete`, `applied_at` = время
    коммита закрытия W12 `c190b7b`, задним числом).
  - **w12-08, w12-09, w12-10** — не описывали ни одного схемного изменения
    (флоу/таблицы/поля/переменной): это фиксация создания и удаления
    *тестовых записей* (фикстура ивента + регистрации для живого позитива
    W12) внутри уже существующих таблиц `events`/`registrations`, с
    `object_id`, равным id самой фикстуры, а не таблицы — отсюда
    расхождение B4. `migrations` по назначению не про данные, а про
    инстанс. Живое состояние проверено (фикстур в `events`/`registrations`
    нет, флоу `lifecycle` жив и `ENABLED`) и уже задокументировано в
    журнале W12 — с одобрения владельца три строки удалены как ошибочно
    заведённые, а не как правка истории.
  - **w45-01…05, w46-01…04** — `commit` указывал на хэш из локальной
    feature-ветки (`ca3d690`, `64221f7`, `0003f95`), который не пережил
    squash-merge и не существует ни в одном рефе репозитория. Заменены на
    фактические хэши смержённых PR: `9c8565d` (#75, W45), `4f8cd72` (#76,
    W46) — оба проверены `git log -1 --format='%H %P'` (один родитель,
    настоящий squash).
  - Итог: `tools/check-migrations.py` → `EXIT 0`.
- **Сценарий 1 (STF-2, `checkin-api`)** — участник пытается отметить
  участника → отказ. Живой различающий прогон на **опубликованной**
  версии `checkin-api` (`rKoDYtiIVdbzlW59b57uH`, не менялась с W32):
  - Временный флоу `tmp-w15-forge-initdata` (создан и удалён в этой же
    сессии, `migrations` w15-00/w15-01) — **не своя крипта**: HMAC считает
    piece `@aiqadam/qadam-crypto : hmac-signature` (та же операция, что
    `fn-hmac-init-data` делает в обратную сторону при верификации), участок
    подписи QR получен настоящим `callFlow → fn-sign-qr`. Подпись QR
    `aIxmwbnzb_` для `(demo, 322876545)` совпала с исторически
    задокументированным значением из W26 — независимое подтверждение, что
    `QR_SIGNING_KEY` тот же.
  - **Негативный прогон**: `controllerId 8255904812` — реальный
    зарегистрированный участник (`w28test`, `mu43al95bl1l`), но **не
    staff** ивента `demo` (обе строки `event_staff` для `demo` — отозваны).
    `curl` на опубликованный `/sync` с валидным подделанным `initData` +
    настоящим QR `demo-322876545` → `403 {"status":"forbidden","text":"Нет
    прав на чекин этого ивента"}`.
  - **Позитивный контроль** (доказывает, что фильтр не fail-closed
    всегда): та же пара `initData`/QR, временно вставлена активная строка
    `event_staff (demo, 8255904812)` без `revoked_at` → тот же запрос →
    `200 {"status":"already","text":"Уже отмечен в 18:49"}` (реальный
    `checked_in_at` регистрации `demo-322876545`). Временная строка удалена
    сразу после, `event_staff` вернулась к исходным двум отозванным строкам.
  - Разрешение построить временный флоу и подделать `initData` — решение
    владельца при взятии этого пункта (классификатор auto mode заблокировал
    первую попытку как чувствительное действие, подтверждено явно).
- **Сценарий 3 (IDM-4, `tg-router`)** — один `update_id` дважды → одна
