## Цель

Вердикт владельца 2026-09-19: решение Q51/W44 «ручной ввод `telegram_id` остаётся
запасным путём» отменено. Ввод контролёра — по логину Telegram (`@username`),
поиск — инлайн в секции (шит-попап убран), одна кнопка «Добавить».

| Артефакт | ID / имя | Каталог |

| i18n-ключи `manage.staff.login_*` | `i18n/ru.json` | — |

Живой проект не меняется (`manage-api` без правок: `staff_search` + `staff_add`
как были) — `catalog/flows/manage-api.md` не трогаем.

## Решение

- Резолв логина — на клиенте: точное совпадение `username` (без `@`,
  регистронезависимо) среди кандидатов `staff_search` → `staff_add` с найденным
  `telegram_id`. Сервер по-прежнему принимает только цифры (DAT-1: решение
  и запись только по `telegram_id`) — бэкенд не менялся.
- Кого бот не видел (нет в `users`) — добавить нельзя: `staff_search` его не
  вернёт, кнопка покажет `login_not_found` («человек должен хотя бы раз открыть
  бота»). Это цена отмены ручного ввода ID, принята вердиктом.
- Совпадения по имени тоже видны списком инлайн (поиск `staff_search` ищет и по
  имени) — у каждой строки своя кнопка «Добавить»; главная кнопка добавляет по
  точному логину.
