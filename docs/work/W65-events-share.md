## Цель

С экрана `#/events` обычный пользователь отправляет событие в Telegram или
копирует диплинк — с карточки «Будущих» и с билета «Моих билетов».

### Замечания

1. **на будущее** — `id="share"` повторяется на каждой карточке
   (`miniapp/src/routes/Events.tsx:631` и `:755`): id в HTML обязан быть
   уникальным, `getElementById('share')` вернёт первый. Поведение не ломается
   (React вешает обработчики, CSS по id не таргетит), и это повтор уже
   существующих `id="ticket"`/`id="register"`/`id="scan"`; для новых элементов
   лучше класс или `data-`. Отмечено владельцем в журнале.
2. **на будущее** — кнопка «Поделиться» на карточке рендерится по `!past`
   безусловно, тогда как кнопка регистрации гейтится `ev.registerLink`
   (`Events.tsx:753` против `:684`). Если `BOT_USERNAME` не задан, `events-api`
   отдаёт `registerLink: ''`: карточка потеряет «Зарегистрироваться», но
   оставит «Поделиться» с пустой ссылкой. В рабочей конфигурации недостижимо;
   защитный `ev.registerLink &&` сделал бы поведение согласованным.
3. **на будущее** — в таблице «Что построено» назван `prototypes/proto.js`, но
   этот файл пакет не менял (диф — только `prototypes/app.js`; `PROTO.copy`
   существовал раньше). Мелочь, но журнал должен совпадать с дифом.
