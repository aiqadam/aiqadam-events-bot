## Журнал

- **2026-09-15** — `step_10`: вместо семи командных сравнений — правило
  «`/start` — три исхода (deep link / меню / молчание), любая другая команда —
  `menu` без `badPayload`». `commandArgs` из возврата убран (читал только
  `manage-open`); вход `step_10` не трогали — удалить ключ из `input` через
  `ap_update_step` нельзя (merge-семантика: не упомянутый проп остаётся),
  а `delete+recreate` потерял бы sample data.
- **2026-09-15** — ветка `manage_open` и `step_26` сняты одним
  `ap_delete_branch` (index 6), `ap_validate_flow` чист. `menu.json` перед
  удалением проверен: кнопка «Создать ивент» — `web_app` на `#/manage`, к
  `manage-open` не ходит, callback-кнопки — свои; `manage-open` нигде, кроме
  `step_26`, не вызывался.
- **2026-09-15** — чекер писался под реальный экспорт, и это дважды окупилось:
  (1) в экспорте `settings.sourceCode` — объект `{code, packageJson}`, а не
  строка (первая версия чекера упала `TypeError`); (2) самопроверка сразу
  нашла дыру — сеть 1 не смотрела `sourceCode` (команда в коде не ловилась) и
  `switch`/`includes` не видели member-выражений (`inputs.command`).
  Ложное срабатывание нашлось на своём же коде: `command !== ''` — проверка
  «команды нет»; пустой литерал из сравнений исключён.
- **2026-09-15** — первое же включение хука поймало то, чего не видит глаз:
  у нового `tools/check-commands.py` не было исполняемого бита (хук вызывает
  файл напрямую) — коммит заблокирован, бит добавлен отдельным коммитом.
- **2026-09-15** — решение по границе: чекер запускается на **каждом** флоу,
  а не только на telegram-триггерном: подфлоу может получить `command` пропом
  (так делал `manage-open`). Требование «вход `/start` есть» — глобальное:
  ноль сравнений командной переменной со `start` валит проверку, чтобы разбор
  нельзя было молча удалить.

### Круг 1 — 2026-09-15

- **Ревьюер**: агент-ревьюер (независимый) · **Дата**: 2026-09-15 · **Вердикт**: есть замечания

#### Замечания

1. **блокер** — `tools/check-commands.py` обходится тривиально, и правило
   ADR-0025 держится не так крепко, как заявлено. Демонстрация на **реальном**
   `flows/tg-router.json`: в `step_10` добавлена ветка
   `} else if (command === "events") { route = 'events_list'; }` (двойные
   кавычки — единственное отличие от соседней ветки `start`) — чекер отвечает
   `нарушений: 0`, код возврата 0. Хук и CI такую команду пропустят. Тот же
   результат у вычисляемой строки (`command === ('ev' + 'ents')`,
   `` command === `events` ``), массива через переменную
   (`const BAD = 'events'; const LIST = [BAD]; if (LIST.includes(command))`),
   карты (`if (MAP[command])`) и `command.endsWith('vents')`. Причины:
   `COMPARE_RE` ловит только одинарные кавычки и только литерал сразу за
   оператором; `SLASH_RE` срабатывает лишь на слэш-форме; элементы массива
   проверяются только там, где объявлены строкой. Почему это блокер: W40 и
   ADR-0025 продают скрипт как «детерминированную проверку», а самая
   вероятная будущая мутация — «добавлю ещё одну команду» — проходит мимо
   него, причём в форме, неотличимой от стиля ветки `start`. До повторного
   ревью: (а) ловить двойные кавычки и шаблонные литералы; (б) считать
   нарушением любое сравнение командной переменной с недоказуемым `'start'`
   (fail-closed: `===` с выражением, `.endsWith()`, `MAP[command]`);
   (в) добавить эти формы в `self_test()` — сейчас самопроверка их не видит
   и подтверждает ложную уверенность.

### Круг 2 — повторное ревью после исправления блокера (коммит `59b7627`)

- **Ревьюер**: агент-ревьюер (независимый), повторное ревью · **Дата**: 2026-09-15 · **Вердикт**: есть замечания

#### Замечания

1. **блокер** — обходы круга 1 закрыты, но чекер по-прежнему пропускает
   команду, если командная переменная обёрнута в вызов/скобки или контейнер
   собран не литералом. Проверка — на копии **реального**
   `flows/tg-router.json` (правка только в temp, репозиторий не тронут);
   каждый пример ниже даёт `нарушений: 0`, код возврата 0:
   - `if (command.trim() === 'events') route = 'events_list';` — в
     `comparisons()` операнд слева обрывается на `)` и выходит пустым, до
     проверки дело не доходит. Тот же класс: `command.toLowerCase() === 'events'`,
     `(command) === 'events'`, `String(command) === 'events'`,
     `command.slice(0, 2) === 'ev'`;
   - `switch (command.toLowerCase()) { case 'events': … }` — `SWITCH_RE`
     признаёт только голый идентификатор в скобках, тело не проверяется;
   - `const L = ['start']; L.push('events'); if (L.includes(command)) …` —
     контейнер проверяется по объявлению, последующие изменения не видны;
   - `const L = ['start'].concat(['events']); if (L.includes(command)) …` —
     `ARRAY_RE` обрезает объявление по первому `]` и **считает** контейнер
     равным `['start']`. Это уже не «неподдержанная форма», а ошибка
     разбора: докстринг обещает «элементы обязаны быть литералами»;
   - тот же класс — `Object.keys({events:1}).includes(command)`,
     `/^ev/.test(command)`, `new Set(['start','events']).has(command)`,
     `Map.get(command)`, `({ start:'menu', events:'x' })[command]`,
     `command?.endsWith('vents')`, `command['endsWith']('vents')`,
     `command[0] === 'e' && command[1] === 'v'`.
   Почему блокер: обязательство, ради которого пакет заведён, —
   «fail-closed: разрешено только доказуемое». Нормализация
   (`trim`/`toLowerCase`) перед сравнением — правдоподобный стиль, а
   `push`/`concat` и `Object.keys(…)` — обычный способ собрать список
   известных команд; чекер не валит именно те мутации, против которых он
   заведён. Речь не о погоне за обфускацией (`command[0]`, `charCodeAt` —
   заведомо мимо), а о формах, которые автор флоу напишет не задумываясь.
   Что может закрыть дыру (чинит владелец, не ревьюер): (а) операнд в
   `comparisons()` брать с балансировкой скобок, а `command.trim()`,
   `(command)`, `String(command)` считать «обёрнутой командой»;
   (б) `SWITCH_RE` — допускать вызов/скобки вокруг субъекта; (в) `ARRAY_RE` —
   требовать, чтобы `]` закрывал объявление (иначе контейнер недоказуем), а
   `push`/`unshift`/`splice`/`concat` на нём — нарушение; (г) `.has`/`.get`/
   `.test` с командной переменной — нарушение; (д) все проходящие формы —
   в `self_test()`.

2. **на будущее** — ложное срабатывание: `switch (command) { case ('start'): … }`
   (валидный, хоть и редкий, стиль) даёт `case с не-литералом "('start')"`.
   Единственное найденное ложное срабатывание, не блокирует. Заодно строка
   докстринга «`flows/_manifest.json` можно не исключать — он пропускается
   сам» неточна: манифест не пропускается, а сканируется как текстовый файл
   (`check_slash`) и просто не даёт нарушений; из-за этого счётчик «файлов
   строк» на единицу больше числа файлов `i18n/`.

## Хвосты и блокеры

- **Живые прогоны ждут человека:** «старая команда отвечает меню» проверяется
  только реальным апдейтом от человека (подделать `initData`/команду нельзя);
  нужен один заход владельца: отправить любую старую команду (`/events`) и
  убедиться, что пришла карточка меню, затем `/start` — меню.
- `check-migrations.py` требует ключ платформы и сеть; миграционные строки
  пакета вставляются после коммита (в них фиксируется его hash).
