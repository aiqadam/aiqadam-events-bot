## Цель

залить их в рабочую копию на инстансе (таблица `strings`) флоу `i18n-sync`
и зафиксировать контракт фолбэка так, чтобы отсутствующий перевод давал `ru`,
а не пустоту.

Граница с W2: subflow `fn-t` собирает агент W2. W3 отвечает за файлы строк,
таблицу `strings` и `i18n-sync`; контракт `fn-t` уточнён в
[I18N.md](../I18N.md), а не реализацией.

## Как проверено

Логика дифа проверена локально на файлах репозитория (13 сценариев), затем
всё существенное перепроверено прогонами на инстансе.

### Локально (Node, чистая функция step_5 на реальных `i18n/*.json`)

- пустая таблица → `to_create = 577`, `to_update = 0`, `to_delete = 0`;
- повторный прогон поверх результата → `changed = 0`;
- изменённое значение → **один `update`**, не пара create+delete;
- дубль `(key, lang)` → удаляется **поздний**, ранний остаётся;
- ключ, которого больше нет в файле → удаляется;
- строка с `lang = de` → удаляется, попадает в `foreign_rows_removed`;
- `uz.json` отдаёт 404 → `to_create/update/delete = 0`, `coverage.uz = null`,
  `skipped_langs = ["uz — HTTP 404"]`;
- битый JSON → тот же результат, что 404;
- пустое значение в файле → строка не заводится, попадает в `dropped_empty_values`;
- пустое значение поверх существующей строки → строка **удаляется**, а не обнуляется;
- ключ есть в `uz`, но нет в `ru` → `missing_in_fallback`;
- ключи `«ключ по-русски»` и `«reg space»` → `bad_keys`, в таблицу не едут;
- все три файла отдают 5xx → таблица не меняется вовсе.

  языка, `changed = 0`, пять лежавших в таблице строк не тронуты. Это и есть
  проверка «404 не стирает строки» на живой платформе.
- **Прогон `rymJKwKjjFBMHL1q0ZAoX`** — URL на ветку `w03-i18n`. Создано 573

  (`_probe.a`), правок ноль. `ap_list_tables`: `strings` → **`rowCount: 577`**,

- **Прогон `6RxVxKGs3VEjCXJtShdG4`** — повторный, без изменений в файлах.

### Чего проверить не удалось

- `fn-t` не существует (пакет W2), поэтому фолбэк проверен **на уровне данных**:
  таблица приведена в форму, которую контракт `fn-t` требует. Сквозной
  «ключ → русская строка при `lang = uz`» проверяется в W2;
- прогон по URL ветки `main` возможен только после мержа PR. Сейчас на `main`
  файлов нет, и такой прогон — это как раз проверенный сценарий «язык
  не скачался, ничего не трогаем».

### Замечания

1. **важно** — **каталог расходится с живой таблицей: не 577 строк, а 573** —
   `catalog/tables/strings.md`, `catalog/overview.md`, `docs/STATUS.md`
   («**577 строк**») против `ap_list_tables` → `strings` `rowCount: 573`.
   `ap_find_records` показывает, каких записей нет: `checkin.ok` есть только
   в `en`, `checkin.already` — только в `uz`; отсутствуют `checkin.ok/{ru,uz}`
   и `checkin.already/{ru,en}` — ровно те четыре строки, которые засеял агент W2
   (видны в `step_4` прогона `jPeXwrPYylmqzUFFMOEpD`) и, судя по всему, за собой
   удалил. Дублей при этом нет: 191 + 191 + 191 = 573, ровно по одному ключу
   меньше в каждом языке. Почему важно: (а) чек-лист «каталог совпадает с живым
   проектом» сейчас не выполняется; (б) в живом словаре не хватает четырёх
   настоящих пользовательских строк чекина, и суточный прогон их **не вернёт** —
   URL смотрят на `main`, где файлов до мержа нет; (в) жёсткое число строк
   в каталоге — утверждение, которое ломает любой сторонний агент. Разумнее
   писать не «577 строк», а «193 `ru` / 192 `uz` / 192 `en` по файлам репозитория,
   приводится прогоном `i18n-sync`».

2. **важно** — **опубликованная конфигурация ни разу не выполнялась: то, что
   URL шагов 1–3 действительно смотрят на `main`, ничем не подтверждено** —
   `i18n-sync`, шаги `step_1`/`step_2`/`step_3`. Все три последних прогона шли
   по ветке: в `52sRON9cTFEEn8mPJnYbb` тело `step_1` содержит `_selftest.fallback`,
   которого на `main` нет. Прогон по `main` (`jPeXwrPYylmqzUFFMOEpD`, 16:38:33)
   был **до** переключения URL на ветку, а после обратного переключения и
   `ap_lock_and_publish` не было ни одного прогона — ни `TESTING`, ни `PRODUCTION`.
   Средствами MCP конфигурацию PIECE-шага прочитать нельзя (`ap_flow_structure`
   отдаёт только тип и `configStatus`, `ap_read_step_code` — только CODE), так что
   ревью это утверждение проверить не может в принципе. Почему важно: если хотя бы
   один из трёх URL остался на `w03-i18n` (частичное переключение — самая
   вероятная ошибка), после мержа и удаления ветки этот язык будет вечно уходить
   в `skipped_langs`, а прогон при этом будет **SUCCEEDED** — тот же класс
   молчаливого отказа, который уже стоил владельцу отладки. Лечится одним
   прогоном после публикации: ожидание — три 404 и `changed: 0`, таблица не
   тронута, а в `skipped_langs` видны все три языка (и по коду 404, а не
   по пустоте, что попутно подтверждает нормализацию вывода `http`).

3. **важно** — **ответ HTTP 200 с валидным, но пустым JSON-объектом стирает язык
   целиком** — `i18n-sync`, `step_5`, функция `parseFile` + раздел «Диф».
   `parseFile` считает язык доехавшим при любом JSON-объекте, включая `{}`;
   тогда `wanted[lang]` пуст, все существующие строки языка попадают в ветку
   «ключа в файле больше нет» и уходят в `delete_ids`. 404, 5xx и битый JSON
   обработаны, а `{}` — нет. Один неудачный коммит в `i18n/ru.json` (пустой
   объект, обрезанный файл, случайный `{}` при мерже) удалит все 193 русские
   строки, а `ru` — единственный язык, на который есть фолбэк: бот покажет сырые
   ключи во всём интерфейсе, и вернуть их сможет только следующий прогон **после**

## Хвосты и блокеры

- **Первый прогон по `main` — только после мержа PR.** До этого суточный прогон
  успешно завершается, ничего не меняя (проверено). После мержа стоит запустить
  флоу руками, не дожидаясь 04:00, и убедиться, что `skipped_langs` пуст.
- **Инвариант I18N-2 закрывается не здесь.** W3 даёт словарь; «ни одной строки
  литералом» проверяется в ревью каждого следующего пакета. Если при сборке
  W4–W14 обнаружится нехватка ключа — ключ добавляется в `i18n/*.json`
  тем пакетом, а не выдумывается литералом на месте.
- **`fn-t` за W2.** Контракт (порядок разрешения, плоский `vars`, неизвестный
  плейсхолдер остаётся как есть, `lang` вне трёх языков = сразу фолбэк) описан
  в [I18N.md](../I18N.md#fn-t). Расхождение реализации с этим текстом —
  дефект W2, а не W3.
- **Чтение таблицы целиком** в `step_4` упрётся в пагинацию, если ключей станет
  на порядок больше. Сейчас 577 строк читаются одним вызовом за 0,5 с.
