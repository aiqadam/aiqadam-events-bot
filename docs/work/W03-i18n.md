## Цель

Завести строки локализации как версионируемый артефакт (`i18n/{ru,uz,en}.json`),
залить их в рабочую копию на инстансе (таблица `strings`) флоу `i18n-sync`
и зафиксировать контракт фолбэка так, чтобы отсутствующий перевод давал `ru`,
а не пустоту.

Граница с W2: subflow `fn-t` собирает агент W2. W3 отвечает за файлы строк,
таблицу `strings` и `i18n-sync`; контракт `fn-t` уточнён в
[I18N.md](../I18N.md), а не реализацией.

## Как проверено

Логика дифа проверена локально на файлах репозитория — **35 утверждений**
в двух наборах (26 по дифу в целом, 9 по предохранителю), провалов нет.
Набор рос по кругам ревью: 13 сценариев в первой сборке, +7 после первого
круга, +сценарии порога по парам после второго. Затем всё существенное
перепроверено прогонами на инстансе.

### Локально (Node, чистая функция step_5 на реальных `i18n/*.json`)

- пустая таблица → `to_create = 607`, `to_update = 0`, `to_delete = 0`;
- повторный прогон поверх результата → `changed = 0`;
- изменённое значение → **один `update`**, не пара create+delete;
- дубль `(key, lang)` → удаляется **поздний**, ранний остаётся;
- ключ, которого больше нет в файле → удаляется;
- строка с `lang = de` → удаляется, попадает в `foreign_rows_removed`;
- `uz.json` отдаёт 404 → `to_create/update/delete = 0`, `coverage.uz = null`,
  `skipped_langs = ["uz — HTTP 404"]`;
- битый JSON → тот же результат, что 404;
- пустое значение в файле → строка не заводится, попадает в `dropped_empty_values`;
- пустое значение поверх существующей строки → строка **удаляется**, а не обнуляется;
- ключ есть в `uz`, но нет в `ru` → `missing_in_fallback`;
- ключи `«ключ по-русски»` и `«reg space»` → `bad_keys`, в таблицу не едут;
- `event.card.btn_map` создаётся на все три языка — ключи, запрошенные W2,
  действительно доезжают.

Добавлено после ревью:

- **HTTP 200 с `{}`** → `to_delete = 0`, `skipped_langs = ["ru — в файле ноль
  пригодных ключей, язык не тронут"]`, `coverage.ru = null` (замечание 3);
- **файл, обрезанный до трети** → `to_delete = 0`, в `skipped_langs` числа:
  «в файле 67 ключей против 203 ключей в таблице»;
- **ровно половина ключей** → порог **не** срабатывает, удаление идёт
  (`to_delete = 101`) — граница проверена с двух сторон;
- **минус один ключ** → `to_delete = 1`, язык не пропущен: обычные правки
  порогом не блокируются;
- **пустая таблица + `ru = {}`** → `ru` пропущен, `uz`/`en` всё равно залиты:
  порог у языков независимый;
- **все три файла отдают 5xx** → таблица не меняется **ни на одну запись**,
  включая мусорную строку с `lang = de` (`to_delete = 0`) — замечание 9;
- **доехал только `ru`** → мусорная строка удаляется (`to_delete = 1`,
  `foreign_rows_removed = ["de:menu.title"]`).

### Чего проверить не удалось

- **Конфигурацию PIECE-шагов средствами MCP прочитать нельзя** — ни URL,
  ни `failureMode`, ни cron; владельцу пакета REST запрещён
  ([ADR-0006](../adr/0006-rest-read-only-for-review.md)). Это ограничение
  инструментов, а не пропуск: вместо чтения конфигурации оставлен прогон
  `uTcYfup7ESNVRKrwd0FUK` (воспроизведён в `v0xePCQ7OpRIPEbgAYZKw`), который
  **различает** верную и неверную конфигурацию. Приём описан
  в [ARCHITECTURE](../ARCHITECTURE.md#ограничения-mcp-о-которые-спотыкаешься-при-правке-шагов).
  **Постфактум закрыто ревьюером:** экспорт опубликованной версии по ADR-0006
  подтвердил cron, таймзону, три URL на `main` и `failureMode` — детали
  и разделение «что чем закрыто» в «Хвостах»;
- **сквозной фолбэк через сам `fn-t`** (а не через его копию) — не проверял
  сознательно: это флоу пакета W2, `ap_test_flow` перезаписал бы его sample
  data. Копия побайтная, логика та же;
- **содержательный прогон по `main`** — принципиально невозможен до мержа PR:
  файлов на `main` ещё нет. Пункт **не закрываю молча**: он закрывается сразу
  после мержа одним запуском флоу руками, ожидание — `skipped_langs` пуст
  и `changed: 0` (словарь в таблице уже актуален). До этого момента поведение
  проверено ровно как сценарий «язык не скачался, ничего не трогаем»,
  и суточный прогон вреда не наносит.

    Правка на одно слово: субъект «ревьюер» → «владелец пакета» (либо

    прогон* `v0xePCQ7OpRIPEbgAYZKw` показывает, что **published совпадает
    с draft**». Строго прогон показывает меньше: `TESTING` исполняет draft,
    значит наблюдаемо лишь то, что **три URL draft-версии** смотрят на `main`;
    вместе с экспортом это даёт совпадение draft и published **по URL**,
    а не равенство версий — `cronExpression`, `timezone` и `failureMode`
    draft-версии не наблюдал никто. Настоящее основание для «draft = published»
    в журнале есть, но другое и процедурное: прогон сделан сразу после
    `ap_lock_and_publish`, без правок между. Главный вывод владельца при этом
    верен и его не отменяю: ни один довод не покрывает другой, окольная проверка
    временем потраченным не была. Уточнить стоит только формулировку — иначе
    W4+ решит, что различающий прогон закрывает равенство версий целиком,
    и перестанет публиковать перед доказательным прогоном.

  `authType`, `filters` подтверждены только таблицей координатора.
- **Число 35** локальных утверждений — набор не коммитится, проверить
  нечем; правило владельца «число либо получено командой, либо не пишется»
  считаю достаточным ответом.
- **Построчная сверка 607 значений** с файлами — выборочно: сверены все 203
  ключа `ru` по составу и `lang = ru/uz/en` по количеству, значения — точечно.

#### Вывод

Четыре пункта третьего круга закрыты, и два из них — лучше, чем просили:
владелец сам нашёл завышенное число и вывел из него правило, а дату из
`catalog/project.md` убрал вместо обновления, чем закрыл источник рецидива,
а не его очередную копию. Правки инстанс не задевали, ничего рядом не сломали:
10 флоу, 11/11 valid, `strings` 607 строк, `step_5` чист, границы пакета целы,
AppSec-проверки по файлам проходят полностью.

Мержу мешает один пункт — замечание 19, правка одного слова в
`docs/work/README.md`. Причина, по которой я не понижаю его до «на будущее»:
этот файл — то место, куда `CLAUDE.md` отправляет за правилами работы, и жирная
строка в нём говорит следующему ревьюеру, что обязательный блок 1a невыполним.
Ровно эту слепоту ADR-0006 и снимал; закрепить её в нормативном документе
дороже, чем поправить субъект в предложении. Замечания 20–23 вердикту
не мешают.

Проверка замечания 19 — это чтение дифа, инстанс не затрагивается вовсе.
Поэтому полный пятый круг под него не нужен: достаточно короткой сверки
четырёх строк (`docs/work/README.md`, плюс, если владелец захочет,
`catalog/overview.md`, `catalog/flows/i18n-sync.md` и описание PR) — после неё

## Хвосты и блокеры

- **Первый содержательный прогон по `main` — только после мержа PR.** Это
  единственный пункт, который до мержа непроверяем в принципе: файлов на `main`
  нет. Он **не закрыт молча** — закрывается сразу после мержа одним ручным
  запуском флоу; ожидание: `skipped_langs` пуст, `changed: 0` (словарь
  в таблице уже актуален, залит с ветки). До этого суточный прогон успешно
  завершается, ничего не меняя, — проверено прогоном `uTcYfup7ESNVRKrwd0FUK`.
  То, что все три URL смотрят именно на `main`, доказано тем же прогоном
  (три 404 против 200 с ветки).
- **Инвариант I18N-2 закрывается не здесь.** W3 даёт словарь; «ни одной строки
  литералом» проверяется в ревью каждого следующего пакета. Если при сборке
  W4–W14 обнаружится нехватка ключа — ключ добавляется в `i18n/*.json`
  тем пакетом, а не выдумывается литералом на месте.
- **`fn-t` за W2.** Контракт (порядок разрешения, плоский `vars`, неизвестный
  плейсхолдер остаётся как есть, `lang` вне трёх языков = сразу фолбэк) описан
  в [I18N.md](../I18N.md#fn-t). Расхождение реализации с этим текстом —
  дефект W2, а не W3.
- **Чтение таблицы целиком** в `step_4` упрётся в пагинацию, если ключей станет
  на порядок больше. Сейчас 607 строк читаются одним вызовом за 0,5 с.
- **Шесть мёртвых входов в `step_5` останутся** — удалить ключ из `input`
  средствами MCP невозможно (merge-семантика). Они обнулены и описаны
  в каталоге; уберутся, если шаг когда-нибудь будет пересоздаваться
  (например, при сборке `events-prod` по каталогу в W15 — там их просто
  не надо заводить).
- **Порог предохранителя блокирует сокращение словаря больше чем вдвое.**
  Если такое сокращение когда-нибудь понадобится осознанно, его придётся
  провести в два прогона или временно снять порог. Цена названа
  в [I18N.md](../I18N.md#предохранитель-обрезанный-файл-не-стирает-язык).
  Порог считает **пары `(key, lang)`**, поэтому дубли в таблице на него
  не влияют и дедуп он не блокирует — если кто-то будет «упрощать» этот
  блок, менять единицу измерения нельзя.
- **Конфигурация шагов — закрыта фактом, хвоста больше нет.** Пункт висел
  три круга как непроверяемый: MCP не отдаёт `settings.input` PIECE-шагов,
  а по расписанию флоу ещё не запускался (`ap_list_runs`,
  `environment: PRODUCTION` → `count: 0`). Правила изменились —
  [ADR-0006](../adr/0006-rest-read-only-for-review.md) разрешил **ревьюеру**
  `GET`-запросы к REST ровно для того, чего не отдаёт MCP. Экспорт
  опубликованной версии `i18n-sync` (снят координатором, данные приведены
  как есть):

  | Шаг | Что подтверждено |
  | --- | --- |
  | `trigger` | `cronExpression: "0 4 * * *"`, `timezone: "Asia/Tashkent"` |
  | `step_1..3` | `url` = `…/aiqadam-events-bot/main/i18n/{ru,uz,en}.json` — все три на **`main`**, не на ветке; `failureMode: "continue_all"`, `timeout: 30`, `authType: "NONE"` |
  | `step_4` | `table_id: qi6bBTL7plRGBgFUfli8w`, `filters: []` |
  | `step_6` | `values` = `{{step_5['output'].create_values}}` |

  То есть подтверждено ровно то, что я доказывал окольным путём, — включая
  `failureMode: continue_all`, на котором держится вся логика отказа
  («язык не скачался — не трогаем»).

  **REST я не использовал и не могу**: по ADR-0006 это инструмент
  проверяющего, владельцу пакета он не разрешён ни для чего. Данные взяты
  от координатора, я их не перепроверял — источник назван честно.

  **Что чем закрыто, чтобы не смешивать два довода:**
  - *экспорт* показывает **опубликованную** конфигурацию — то есть URL, cron
    и таймзону;
  - *различающий прогон* `v0xePCQ7OpRIPEbgAYZKw` показывает, что
    **published совпадает с draft** — чего экспорт как раз не показывает,
    потому что прогоны `TESTING` исполняют draft.

  Ни один из двух доводов не покрывает другой, поэтому оба остаются в силе.
- **[Q16](../OPEN-QUESTIONS.md#q16) и [Q17](../OPEN-QUESTIONS.md#q17)** заведены
  этим пакетом, но решаются не в нём: Q16 — до W14, Q17 — до W7.
