## Цель

Завести строки локализации как версионируемый артефакт (`i18n/{ru,uz,en}.json`),
залить их в рабочую копию на инстансе (таблица `strings`) флоу `i18n-sync`
и зафиксировать контракт фолбэка так, чтобы отсутствующий перевод давал `ru`,
а не пустоту.

Граница с W2: subflow `fn-t` собирает агент W2. W3 отвечает за файлы строк,
таблицу `strings` и `i18n-sync`; контракт `fn-t` уточнён в
[I18N.md](../I18N.md), а не реализацией.

## Как проверено

Логика дифа проверена локально на файлах репозитория (13 сценариев), затем
всё существенное перепроверено прогонами на инстансе.

### Локально (Node, чистая функция step_5 на реальных `i18n/*.json`)

- пустая таблица → `to_create = 577`, `to_update = 0`, `to_delete = 0`;
- повторный прогон поверх результата → `changed = 0`;
- изменённое значение → **один `update`**, не пара create+delete;
- дубль `(key, lang)` → удаляется **поздний**, ранний остаётся;
- ключ, которого больше нет в файле → удаляется;
- строка с `lang = de` → удаляется, попадает в `foreign_rows_removed`;
- `uz.json` отдаёт 404 → `to_create/update/delete = 0`, `coverage.uz = null`,
  `skipped_langs = ["uz — HTTP 404"]`;
- битый JSON → тот же результат, что 404;
- пустое значение в файле → строка не заводится, попадает в `dropped_empty_values`;
- пустое значение поверх существующей строки → строка **удаляется**, а не обнуляется;
- ключ есть в `uz`, но нет в `ru` → `missing_in_fallback`;
- ключи `«ключ по-русски»` и `«reg space»` → `bad_keys`, в таблицу не едут;
- все три файла отдают 5xx → таблица не меняется вовсе.

### На инстансе

- **Прогон `jPeXwrPYylmqzUFFMOEpD`** — URL на `main`, где файлов ещё нет.
  Все три шага вернули 404, флоу **SUCCEEDED**, `skipped_langs` перечислил три
  языка, `changed = 0`, пять лежавших в таблице строк не тронуты. Это и есть
  проверка «404 не стирает строки» на живой платформе.
- **Прогон `rymJKwKjjFBMHL1q0ZAoX`** — URL на ветку `w03-i18n`. Создано 573
  записи одним вызовом `tables-create-records` (1,3 с), удалена одна лишняя
  (`_probe.a`), правок ноль. `ap_list_tables`: `strings` → **`rowCount: 577`**,
  ровно 193 + 192 + 192.
- **Прогон `6RxVxKGs3VEjCXJtShdG4`** — повторный, без изменений в файлах.
  `step_5`: `{"changed":0,"report":{"rows_before":577,"coverage":{"ru":193,"uz":192,"en":192},
  "to_create":0,"to_update":0,"to_delete":0,"skipped_langs":[],"duplicates_removed":[],
  "untranslated":{"uz":["_selftest.fallback"],"en":["_selftest.fallback"]}}}`.
  Дублей не появилось — это ответ на «второй запуск не должен плодить строки».
- **Прогон `52sRON9cTFEEn8mPJnYbb`** — поверх четырёх намеренно внесённых
  дефектов. Вносил вручную через MCP: испортил значение `reg.consent_pdn.declined/uz`,
  добавил дубль `_selftest.vars/uz`, ключ `reg.obsolete_key/ru`, которого нет
  в файлах, и строку `menu.title/de`. Прогон: `to_update = 1`, `to_delete = 3`,
  `to_create = 0`, `duplicates_removed = ["uz:_selftest.vars"]`,
  `foreign_rows_removed = ["de:menu.title"]`. Испорченное значение восстановлено
  **в той же записи** (`aHmXWFyU6ccRW533Clg9N`), а не пересоздано; удалён именно
  поздний дубль. Таблица вернулась к 577 строкам.
- **Фолбэк, запрос к таблице.** `ap_find_records` по `key = _selftest.fallback`
  вернул **одну** строку — `lang = ru`. Пустых строк для `uz`/`en` не создано:
  именно это и нужно `fn-t`, чтобы уйти в `ru`, а не показать пустоту.
  Для сравнения `key = _selftest.vars` вернул ровно три строки, по одной на язык.
- **Узбекские модификаторы.** `reg.consent_pdn.declined/uz` в таблице:
  `Rozilik boʻlmasa roʻyxatdan oʻtish imkonsiz…` — U+02BB и U+02BC доехали
  через HTTP, JSON и Tables без подмены на `'`.
- **Перевод строки в значении.** `staff.invite.created` хранит реальный `\n`
  перед `{url}` во всех трёх языках — многострочные строки таблицу не ломают.
- **`lang = de` после уборки.** `ap_find_records` по `lang = de` → `count: 0`.
- **Файлы, статические проверки.** Скриптом: `uz`/`en` не содержат ключей,
  отсутствующих в `ru`; набор подстановок `{...}` в каждом переводе совпадает
  с русским (иначе `fn-t` подставил бы не то); ни одного пустого значения;
  **ни одного ASCII-апострофа в `uz.json`** — 78 значений с `ʻ` и 13 с `ʼ`.

### Чего проверить не удалось

- `fn-t` не существует (пакет W2), поэтому фолбэк проверен **на уровне данных**:
  таблица приведена в форму, которую контракт `fn-t` требует. Сквозной
  «ключ → русская строка при `lang = uz`» проверяется в W2;
- прогон по URL ветки `main` возможен только после мержа PR. Сейчас на `main`
  файлов нет, и такой прогон — это как раз проверенный сценарий «язык
  не скачался, ничего не трогаем».

## Журнал

- **2026-09-08** — пакет взят. На старте: `ap_list_flows` → 0 флоу,
  `strings` существует с полями `key` / `lang` / `value` и `rowCount: 0`.
- **2026-09-08** — 193 ключа написаны в одном месте таблицей «ключ → ru/uz/en»
  и разложены в три файла разовым скриптом. Скрипт **не коммитится**: источник
  правды по [I18N.md](../I18N.md) — сами `i18n/*.json`, а генератор рядом с ними
  стал бы вторым описанием одного и того же. Порядок ключей в трёх файлах
  одинаковый — так диф между языками читается глазами.
- **2026-09-08** — решение по триггеру: **cron, а не вебхук.** Вебхук дал бы
  удобный «запустить сейчас», но это неаутентифицированная точка, пишущая
  в таблицу; ради удобства открывать её не стоит, а ручной запуск и так есть
  кнопкой в UI. Расписание — 04:00 по Ташкенту: строки меняются редко,
  и суточной задержки после мержа достаточно.
- **2026-09-08** — решение по алгоритму: **диф, а не clear + insert.**
  Clear + insert идемпотентен «бесплатно», но оставляет окно, в котором таблица
  пуста, и при сбое на вставке стирает локализацию целиком. Диф дороже в коде,
  зато повторный прогон виден как `changed: 0`, а не как «переписали всё ещё раз».
- **2026-09-08** — до сборки прогнал два вызова `ap_run_action`, чтобы не
  угадывать: `tables-create-records` с пустым массивом безобиден (`[]`),
  а `tables-delete-record` с `records_ids: []` **падает** `404 ENTITY_NOT_FOUND`.
  Из-за этого удаление сидит в `LOOP_ON_ITEMS`, а не в отдельном шаге с router'ом:
  пустой цикл — ноль итераций, и ветвление не нужно.
- **2026-09-08** — самая дорогая ошибка сборки. `{{step_1['output'].status}}`
  выглядит правильно и в первом прогоне (файлов на `main` нет, 404) дал
  «ожидаемый» результат `skipped_langs`. На самом деле шаблон отдавал **пустую
  строку**, потому что при ошибке вывод обёрнут в `response`, а при успехе —
  плоский. Заметил только потому, что в отчёте стояло `"ru — HTTP "` без кода:
  пустое значение вместо `404`. Если бы файлы были на `main`, флоу «успешно»
  не залил бы ни строки. Починено передачей всего вывода шага в Code step;
  факт вынесен в [ARCHITECTURE](../ARCHITECTURE.md#qadamы-http-и-tables-на-практике--проверено-на-инстансе-2026-09-08).
- **2026-09-08** — таблица оказалась не пустой: агент W2 засеял 4 строки
  (`checkin.ok`, `checkin.already` на ru/uz/en) под свои проверки `fn-t`.
  Значения совпали с моими файлами посимвольно, поэтому диф их не тронул —
  `to_update = 0`. Повезло; расходись они хоть на пробел, прогон переписал бы
  их под репозиторий, и это правильное поведение, но W2 стоит знать: править
  `strings` руками бессмысленно, текст живёт в JSON.
- **2026-09-08** — фикстура `_selftest.fallback` заведена только в `ru`
  сознательно. Альтернатива — оставить непереведённым живой ключ — означала бы,
  что кто-то из узбекоязычных пользователей увидит русский текст ради теста.
  Служебный ключ с префиксом `_` не показывается никому и проверяет то же самое.
  Второй фикстурой (`_selftest.vars`) W2 сможет проверить подстановку `{a}`/`{b}`
  без риска задеть боевую строку.
- **2026-09-08** — URL зафиксированы на `main`, хотя проверялось на ветке.
  Держать в опубликованном флоу адрес feature-ветки нельзя: она исчезнет после
  мержа, а флоу продолжит по ней ходить. Прогон по `main` до мержа проверен
  отдельно и безопасен — 404 на всех трёх языках ничего не меняет.
- **2026-09-08** — попутный вывод для W14 и W13: `step_5` отдаёт 79 КБ,
  `step_4` — 320 КБ, и платформа такие выводы **выносит в файл**
  (`{fileId, size, url}` вместо данных в логе). Работе это не мешает —
  следующий шаг получает значение целиком, — но читать такой шаг в UI и через
  MCP уже нельзя. Для рассылки на тысячи получателей это значит, что промежуточные
  списки лучше не тащить через выводы шагов.

  опубликован и включён. Каталог снят с `ap_flow_structure` после публикации.

## Хвосты и блокеры

- **Первый прогон по `main` — только после мержа PR.** До этого суточный прогон
  успешно завершается, ничего не меняя (проверено). После мержа стоит запустить
  флоу руками, не дожидаясь 04:00, и убедиться, что `skipped_langs` пуст.
- **Инвариант I18N-2 закрывается не здесь.** W3 даёт словарь; «ни одной строки
  литералом» проверяется в ревью каждого следующего пакета. Если при сборке
  W4–W14 обнаружится нехватка ключа — ключ добавляется в `i18n/*.json`
  тем пакетом, а не выдумывается литералом на месте.
- **`fn-t` за W2.** Контракт (порядок разрешения, плоский `vars`, неизвестный
  плейсхолдер остаётся как есть, `lang` вне трёх языков = сразу фолбэк) описан
  в [I18N.md](../I18N.md#fn-t). Расхождение реализации с этим текстом —
  дефект W2, а не W3.
- **Чтение таблицы целиком** в `step_4` упрётся в пагинацию, если ключей станет
  на порядок больше. Сейчас 577 строк читаются одним вызовом за 0,5 с.
