## Цель

Снять долг локализации: `i18n/uz.json` и `i18n/en.json` доводятся до
**точного** набора ключей `ru.json`, значения импортируются в платформенные

### Замечания

Замечаний нет. Содержательная часть пакета (паритет ключей, плейсхолдеры,
отсутствие «лишних», офлайн-проверки, сборка, поверхность строк по AppSec)

### Что проверено живьём (MCP `app-flow-events-dev`)

- `ap_list_flows` — 32 флоу (31 наш + чужой `ChatBot`), состав совпал с
  `catalog/overview.md`; `flows/_manifest.json` (31, `source: mcp`) покрывает
  все наши флоу, `publishedVersionId`-расхождений не видно.
- `ap_flow_structure(includeInput)` по `tg-router` и `menu`: входы `texts`
  содержат только ссылки `{{$t['…']}}`, литералов нет; `menu/step_12` —
  `format: None`, `menu/step_5` — `MarkdownV2`.
- `ap_read_step_code` `menu/step_4`: перед отправкой в `MarkdownV2` текст
  экранируется (`esc()` по `_*[]()~`>#+\-=|{}.!`), подписи кнопок не
  экранируются (клавиатура разметку не парсит) — новые `uz`/`en` значения не
  могут сломать сообщение.
- `ap_validate_flow` по `menu`, `reg-start`, `checkin-api`, `manage-api`,
  `tg-router` — 0 `invalid`, предупреждений (в т. ч. о недостающих локалях)
  нет.
- Все 205 ключей из `{{$t['…']}}` в живых флоу — литеральные (динамических
  `$t[expr]` нет); 138 добавленных ключей с этим набором не пересекаются.
