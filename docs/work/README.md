# Журналы работ

По файлу на пакет работ: `W05-registration.md`, `W08-checkin-api.md` и так далее.
Индекс со статусами — [../STATUS.md](../STATUS.md).

## Зачем именно так

У каждого файла **один писатель** — агент, взявший пакет. Поэтому параллельные
дорожки из [ROADMAP.md](../ROADMAP.md) не дерутся за один файл. В `STATUS.md`
каждый меняет **свою строку**, а построчные правки git сливает без конфликтов.

Три вещи фиксируются в трёх разных местах, и путать их не надо:

| Что | Где | Кто ведёт |
| --- | --- | --- |
| Состояние системы — что реально построено | [`catalog/`](../../catalog/) | агент после каждого изменения флоу |
| Состояние работ — кто что делает и что готово | `docs/work/` + `STATUS.md` | агент, владеющий пакетом |
| Решения и нерешённое | [`docs/adr/`](../adr/), [OPEN-QUESTIONS.md](../OPEN-QUESTIONS.md) | тот, кто наткнулся |

## Как взять пакет

1. Открыть [../STATUS.md](../STATUS.md), убедиться, что пакет в статусе `не начат`
   и его зависимости в статусе `готов`.
2. Создать `docs/work/WNN-<slug>.md` по [_TEMPLATE.md](_TEMPLATE.md).
3. В `STATUS.md` поменять **свою строку**: статус → `в работе`, владелец, дата.
4. Закоммитить и **сразу запушить** — это и есть взятие пакета.
   Если push отбило, кто-то взял пакет первым: сделать rebase и посмотреть.

Пакет без строки `в работе` считается свободным. Молча работать над чужим пакетом —
худший из возможных вариантов: два агента соберут два разных флоу.

## Пока идёт работа

Журнал ведётся **по ходу, а не задним числом**: в конце сессии восстановить, почему
шаг сделан именно так, уже не получится. Писать стоит то, что не видно из каталога:
почему выбран такой порядок шагов, что не сработало, какие фикстуры использованы.

Найденное противоречие в ТЗ идёт в [OPEN-QUESTIONS.md](../OPEN-QUESTIONS.md) или
правкой [SPEC.md](../SPEC.md) со ссылкой на ADR — **не** в журнал. Журнал никто не
читает при принятии решений.

## Как закрыть пакет

Пакет `готов`, когда одновременно:

- пройден чек-лист пакета из [BACKLOG.md](../BACKLOG.md) — весь, а не «в основном»;
- `catalog/` совпадает с живым проектом;
- журнал дописан: что построено, что осталось хвостом, на чём споткнулись;
- строка в `STATUS.md` переведена в `готов`.

Если часть пакета сделать не удалось — статус `готов` не ставится. Ставится
`заблокирован` с указанием, чего не хватает. Половина пакета, помеченная готовой,
обнаружится на приёмке и будет стоить дороже честного блокера.
