## Цель

Флоу `registration` ([FLOWS.md](../FLOWS.md#registration--регистрация-участника)):
участник переходит по `/start e<id>-<utm>`, получает карточку ивента и место
(с учётом овербукинга), даёт обязательное согласие на обработку данных,
опционально — согласие на рассылку и телефон, получает QR.

## Чек-лист готовности

> Из [BACKLOG.md](../BACKLOG.md#w5-регистрация-участника).

- [ ] согласие на обработку данных — **обязательный** шаг, отказ не создаёт регистрацию (PAR-1)
- [ ] лимит мест: `ceil(capacity × (1 + overbook_pct/100))`, дефолт 40% (OWN-15); пустой `capacity` — без ограничений
- [ ] согласие на рассылку — **отдельный** шаг, отказ **не** мешает регистрации (PAR-2), `consent_marketing` не проставляется побочно
- [ ] `utm` из `?start=e<id>-<utm>` доезжает в `registrations.source` (OWN-6)
- [ ] повторный переход по ссылке не плодит строк и не шлёт второе подтверждение (IDM-1)
- [ ] участнику уходит `sendVenue` + ссылка на Я.Карты из `lat`/`lon` (OWN-2)
- [ ] QR выдан и сходится с `fn-verify-qr`
- [ ] `catalog/` совпадает с живым проектом
