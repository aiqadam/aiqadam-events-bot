## Цель

Форма W33 (OWN-1…OWN-5) пересобирается в пошаговый визард: Основное →
Где и когда → Места → Проверка. Гео — ссылкой Яндекс.Карт, «Взять моё
местоположение» или недавним местом (Q52: интерактивной карты нет).
Публикация заканчивается экраном успеха со ссылкой регистрации, а не прыжком
в чат. Подробности — [BACKLOG W42](../BACKLOG.md#w42-визард-ивента-шаги-и-гео-ссылкой-яндекс-карт),
дублировать не надо.

- **Браузерный прогон (Playwright, Chromium, 390×844, свой статик-сервер
  `dist` + мок `Telegram.WebApp` и `manage-api`) — 34/34 проверок, 0 ошибок
  страницы** (единственная «console: 422» — ожидаемый ответ негативного
  сценария). Что покрыто:
  - список чаптера → «Создать ивент» → шаги 1→4, «Шаг N из 4» и точки;
  - мягкая валидация: пустой шаг 1 пускает (черновик можно вести частями),
    «Окончание раньше начала» — ошибка на месте;

    «41.31108, 69.27974»; `ll=71.41815,51.09049` → «51.09049, 71.41815»;

## Журнал

- **2026-09-16** — взятие пакета. Перед стартом закрыт [Q52](../OPEN-QUESTIONS.md#q52):
  владелец выбрал «тупо ссылка на Яндекс карту» — интерактивной карты
  в продукте нет, «Указать на карте» из прототипа снято, SPEC OWN-1 поправлен
  отдельным коммитом. Границы пакета: `miniapp/src/routes/Manage.tsx`,
  `manage-api` (контракт не менялся), `i18n/ru.json`, каталог. Не трогались:
  `tg-router`, гостевые и чекин-флоу (правило v0.1).
- **2026-09-16** — **сервер:** единственная правка `manage-api` — `step_32`
  добавляет `address`/`lat`/`lon` в `list` **только для своих** (`isAuthor`)
  ивентов с непустым адресом: недавние места визарда, отдельного хранилища
  не заводим. Контракт `load`/`save`/валидация не тронуты (BACKLOG: «manage-api
  сохраняет контракт полей и валидацию»). Публикация `84WomF3biB4Y0kFMbHxoA`,
  снимок через MCP сразу после публикации (`source: mcp`), REST-ключа у агента нет.
- **2026-09-16** — **SPA:** форма переписана в визард. Решения по ходу:
  - черновик **создания** — `localStorage` (`manage.new.draft`: поля + шаг),
    восстанавливается при повторном открытии формы, очищается после успешного
    `save`; для правки черновика нет — данные и так на сервере, а несохранённые
    правки теряются (названо здесь, не спрятано);
  - шаги валидируются **мягко** (формат/согласованность), обязательные поля —
    только на «Опубликовать»; так черновик можно вести частями, а серверная
    валидация остаётся источником правды. Ошибка сервера прыгает на шаг
    с полем (`STEP_OF_FIELD`);
  - статус больше не радиокнопка: «Сохранить черновик» / «Опубликовать» /
    «Сохранить» / «Отменить ивент» — переходы OWN-4 сохранены, отмена
    с подтверждением в карточке (без `window.confirm`);
  - «Недавние места» — только из уже загруженного списка `#/manage`
    (свои ивенты, дедуп по адресу, максимум 5). При прямой ссылке
    `#/manage/:id` списка нет — недавних мест не будет; это цена отсутствия
    второго запроса, названа;
  - «Взять моё местоположение» осталась (`LocationManager` → `geolocation`),
    «Указать на карте» снято (Q52);
  - секция «Контролёры» (W36) показывается на шаге «Проверка» — в визарде
    у неё нет своего шага, а на каждом шаге она была бы мусором.
- **2026-09-16** — **два реальных бага, найденных верификацией, а не ревью:**
  1. после успешного `save` смена `eventId` перезапускала эффект загрузки —
     `load()` сбрасывал `done`/`result` и стирал экран успеха. Эффект переведён
     на `propEventId` (из hash), `load` принимает id; после создания форма
     больше не перезагружается с сервера;
  2. предпросмотр черновика на «Проверке» затемнялся классом `past`
     (opacity 0.7) — снято по скриншотам.
- **2026-09-16** — **визуальная верификация:** headless-прогон 34/34 и 14
  скриншотов; смотрели светлую и тёмную темы, sticky-бар в реальном viewport
  (fullPage-скриншоты его положение искажают). Отдельно проверено: пустой шаг
  пускает, но публикация пустой формы возвращает на шаг 1.
- **2026-09-16** — каталог: `manage-api.md` (форма ответа `list`), раздел
  Mini App в `overview.md` (визард, гео, черновик, экран успеха). `migrations`:
  строка `2026-09-16-w42-01`, `publish`, версия `84WomF3biB4Y0kFMbHxoA`,
  commit — хэш коммита пакета (вставлена сразу после коммита).
