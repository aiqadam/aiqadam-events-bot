# W118. `prototypes/check.mjs` — синтаксическая проверка всех `prototypes/*.js`

- **Статус**: готов
- **Владелец**: агент
- **Волна**: вне волн
- **Зависит от**: `prototypes/check.mjs` (W41)
- **Начат**: 2026-09-28 · **Закрыт**: 2026-09-28

## Цель

`check.mjs` грузит в песочницу только `proto.js`/`data.js`/`scenarios.js`,
а `app.js`/`chat.js` читает как текст — синтаксическая ошибка в них не
ловится. В W117 именно так прошёл блокер (двойной `const`), из-за которого
`app.html` не открывался. Пакет добавляет парсинг каждого `prototypes/*.js`
и валит проверку с именем файла и сообщением.

## Что построено

| Артефакт | Изменение |
|----------|-----------|
| `prototypes/check.mjs` | раздел 0 — `new vm.Script` по каждому `*.js`, строка «синтаксис: N файлов ok» в выводе |
| `.github/workflows/checks.yml` | шаг «Прототипы — синтаксис всех prototypes/*.js и сценарии (W118)» |
| `.githooks/pre-commit` | при изменении `prototypes/*.js` гоняет `check.mjs` (с оговоркой на отсутствие `node`) |

Изменений на инстансе нет: только офлайн-инструменты.

- [x] `catalog/` совпадает с живым проектом (инстанс не тронут).

## Как проверено

- **Норма**: `node prototypes/check.mjs` → `синтаксис: 5 файлов ok`,
  остальные разделы без изменений, EXIT 0.
- **Подсаженный дубль `const` в `app.js`** (тот самый дефект W117) →
  `синтаксис: 4 из 5 файлов ok`, `✗ синтаксис app.js: Identifier 'DUP_X'
  has already been declared`, EXIT 1.
- **Подсаженная незакрытая скобка в `chat.js`** (файл, который в песочницу
  вообще не грузится) → `✗ синтаксис chat.js: Unexpected end of input`,
  EXIT 1. Оба подсаженных файла восстановлены `git checkout --`.
- **Подсаженные ошибки в файлах песочницы `proto.js`/`data.js`/
  `scenarios.js`** → каждый даёт `синтаксис: 4 из 5 файлов ok` и
  `✗ синтаксис <файл>: <сообщение>`, EXIT 1, без падения на
  `vm.runInContext` (правка по ревью, круг 1).
- CI-шаг и pre-commit прогнаны локально: `node prototypes/check.mjs` EXIT 0.

## Журнал

- **2026-09-28** — парсинг вынесен в раздел 0 и идёт **до** загрузки
  песочницы, чтобы ошибка не маскировалась падением `vm.runInContext`.
  Формат строки: `N файлов ok` при полном успехе и `N из M файлов ok` при
  ошибке — так исход виден и глазами, и машиной; BACKLOG просил «N файлов ok»,
  этот вид сохранён.
- **2026-09-28** — проверка добавлена в CI (`checks.yml`) и в pre-commit:
  без этого она запускалась бы только по памяти, а именно на память
  и была жалоба W117. Оговорка `command -v node` в хуке не даёт коммиту
  зависеть от наличия Node на машине.
- **2026-09-28** — правки по ревью (круг 1): (1) раздел 0 при непустом
  `errors` печатает отчёт и выходит **до** загрузки песочницы — иначе ошибка
  в `proto.js`/`data.js`/`scenarios.js` падала на `vm.runInContext` без имени
  файла; (2) regex хука расширен до `\.(js|mjs)$`, чтобы правка самого
  `check.mjs` тоже запускала проверку.

### Замечания

1. **важно** Синтаксическая ошибка в файлах, которые грузятся в песочницу
   (`proto.js`, `data.js`, `scenarios.js`), по-прежнему **не приходит «с именем
   файла и сообщением»**: раздел 0 её ловит и кладёт в `errors`, но прогон
   падает раньше печати отчёта — на `vm.runInContext` / `PROTO.buildScenarios()`
   (`TypeError: ...`), а `process.exit(1)` на `check.mjs:68` обрывает работу до
   блока `ОШИБКИ`. Подсаживал незакрытую скобку в каждый из трёх файлов
   (in-memory: патч `fs.readFileSync` + импорт настоящего `check.mjs`, файлы
   не трогались): EXIT 1 есть, но в выводе — чужой `TypeError`, строки
   `✗ синтаксис <файл>` нет. Итог: критерий BACKLOG «валить проверку с именем
   файла и сообщением» и фраза журнала «ошибка не маскируется падением
   `vm.runInContext`» верны только для `app.js`/`chat.js`; 3 из 5 файлов
   маскируют. Лечится ранним выходом/печатью отчёта сразу после раздела 0
   (пока `errors` ещё виден), а не только для `app.js`/`chat.js`.
   - *Исправлено*: сразу после раздела 0, если `errors` непуст, печатается
     `синтаксис: N из M файлов ok` и список `✗ синтаксис <файл>: <сообщение>`,
     затем `process.exit(1)` — до загрузки песочницы. Проверено подсаженными
     ошибками в `scenarios.js`, `proto.js`, `data.js` — диагностика по файлу
     есть у всех. (2026-09-28)
2. **на будущее** Regex pre-commit `^prototypes/.*\.js$` не матчит
   `prototypes/check.mjs` (`.mjs`). Коммит, меняющий только сам скрипт проверки
   — в том числе коммит этого пакета, — не запускает хук: все четыре
   `*_changed` остаются 0 и срабатывает ранний `exit 0`. Дырой это не является
   (CI на PR проверку всё равно гоняет, и прогон `check.mjs` при этом зелёный),
   но локальная страховка для самого инструмента не работает; расширить до
   `^prototypes/.*\.(js|mjs)$` или добавить `check\.mjs`.
   - *Исправлено*: regex в `.githooks/pre-commit` —
     `^prototypes/.*\.(js|mjs)$`; коммит, меняющий только `check.mjs`,
     снова запускает проверку. (2026-09-28)

**Что подтверждено (не замечания):** раздел 0 действительно перебирает **все**
