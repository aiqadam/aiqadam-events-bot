## Цель

Вернуть ru/uz/en, использовав платформенный механизм переводов `$t`
(ADR-0044 п. 3.2, ADR-0014 «Как воскрешать», первая ветка): строки уезжают
импортом в платформенные переводы, `texts`-карты во входах CODE-шагов
заменяются на `{{$t['key']}}`, `i18n-sync` не воскрешается, `i18n-resolve`
не возвращается. Плюс `pick()` по `language_code` обратно в Mini App.

## Что делаем (план)

1. **Разведка:** как `$t` ведёт себя в CODE-шаге и входе PIECE, как задаётся
   `localeSource` (у живых флоу поле `null`), что происходит на отсутствующем
   ключе, наследуется ли локаль в `callFlow`.
2. **Импорт строк** `i18n/{ru,uz,en}.json` в платформенные переводы
   (`ap_upsert_translations`), `project.defaultLocale` = `ru`.
3. **Миграция `texts`:** в каждом входе CODE-шага значение `{ключ: литерал}`
   становится `{ключ: "{{$t['ключ']}}"}`; `t()` внутри CODE не меняется.
4. **`localeSource`** на входных флоу: `tg-router` (Telegram-апдейт), вебхук-API
   Mini App (локаль из запроса), расписания — по решению разведки.
5. **Mini App:** вернуть `pick()` по `language_code` в `miniapp/src/lib/i18n.ts`.
6. **Документы:** снять приостановку I18N-1/I18N-2 в SPEC, обновить ADR-0014,
   `docs/I18N.md`, каталог.
7. **Публикация, живые прогоны, экспорт** `flows/*.json`, независимое ревью.
