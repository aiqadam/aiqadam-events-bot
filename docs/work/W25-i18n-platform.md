# W25. Возврат i18n на платформенном механизме

- **Статус**: на проверке
- **Владелец**: агент
- **Волна**: v0.1
- **Зависит от**: W24 (готов); qadam-flow#420 закрыт 2026-09-26 (W108)
- **Начат**: 2026-09-27 · **Закрыт**: —

## Цель

Вернуть ru/uz/en, использовав платформенный механизм переводов `$t`
(ADR-0044 п. 3.2, ADR-0014 «Как воскрешать», первая ветка): строки уезжают
импортом в платформенные переводы, `texts`-карты во входах CODE-шагов
заменяются на `{{$t['key']}}`, `i18n-sync` не воскрешается, `i18n-resolve`
не возвращается. Плюс `pick()` по `language_code` обратно в Mini App.

## Что делаем (план)

1. **Разведка:** как `$t` ведёт себя в CODE-шаге и входе PIECE, как задаётся
   `localeSource` (у живых флоу поле `null`), что происходит на отсутствующем
   ключе, наследуется ли локаль в `callFlow`.
2. **Импорт строк** `i18n/{ru,uz,en}.json` в платформенные переводы
   (`ap_upsert_translations`), `project.defaultLocale` = `ru`.
3. **Миграция `texts`:** в каждом входе CODE-шага значение `{ключ: литерал}`
   становится `{ключ: "{{$t['ключ']}}"}`; `t()` внутри CODE не меняется.
4. **`localeSource`** на входных флоу: `tg-router` (Telegram-апдейт), вебхук-API
   Mini App (локаль из запроса), расписания — по решению разведки.
5. **Mini App:** вернуть `pick()` по `language_code` в `miniapp/src/lib/i18n.ts`.
6. **Документы:** снять приостановку I18N-1/I18N-2 в SPEC, обновить ADR-0014,
   `docs/I18N.md`, каталог.
7. **Публикация, живые прогоны, экспорт** `flows/*.json`, независимое ревью.

| A, `lc=en` | | `{"lc":"en","child":{"hello":"Hello"}}` |
| A, `lc=ru` | | `{"lc":"ru","child":{"hello":"Привет"}}` |
| `v8qHq23uUbYms15bI9FFc` | A, без `lc` | шаг `step_2` ❌ `TranslationKeyNotFound` — цепочка пуста без `defaultLocale` |
| B, заголовок `ap-parent-run-locale: uz`, тело `{}` | | `{"lc":"","child":{"hello":"Salom"}}` — вебхук наследует локаль из заголовка |

| B, без заголовка | | шаг ❌ `TranslationKeyNotFound` |

### Замечания

1. **блокер** — ключи `remind.2h`, `remind.24h`, `remind.btn.directions` отсутствуют
   в платформенных переводах проекта, а `reminders/step_8` (тело цикла) на них
   ссылается — `reminders/step_8`. `ap_validate_flow(reminders)` воспроизводимо отдаёт

   исправления шага и чекера повторный `ap_upsert_translations` не делался, а
   `reminders` опубликован строкой `w25-21`). Отсутствующий `$t` валит шаг
   (`TranslationKeyNotFoundError`), поэтому это **регрессия**: до W25 строки были
   литералами и напоминания уходили, теперь сорвутся, как только в цикле появится
   получатель (прогон `LQ3S5WMnCWVxn4E7cBFAa` зелёный только потому, что
   `targets: []`, ноль итераций). Лечение: импортировать три ключа (для

2. **важно** — `tools/check-texts.py` не обходит `continueOnFailureBranches`

   Итог: I18N-2 в этих ветках не выполнен, и чекер их не увидит (как раньше не видел

   мигрировать оба литерала на `{{$t[...]}}` (ключи уже в `ru.json`) и перевыпустить
   `reg-start`/`staff-accept`.

3. **важно** — `flows/_manifest.json` (31) ↔ живой проект (32): на dev есть флоу
   `ChatBot` (`Ap06RmygApT4oFAylYfpu`, триггер `@aiqadam/qadam-forms`), которого нет
