# W43. Регистрация и «Мои билеты» в каталоге `#/events`

- **Статус**: в работе
- **Владелец**: агент
- **Волна**: v0.1 (второй и последний пакет пары W38 → W43, [ROADMAP](../ROADMAP.md#v01--порядок-работ-один-агент-последовательно))
- **Зависит от**: W38 (✅ каталог и `events-api`), W28 (✅ лекало карточки и согласий)
- **Начат**: 2026-09-16 · **Закрыт**: —

## Цель

PAR-3/PAR-4 в целевой форме: каталог `#/events` с табами **«Мои билеты»**
(первым), «Будущие», «Прошедшие»; регистрация на будущий ивент — **внутри
Mini App**, двумя раздельными согласиями (PAR-1, PAR-2); подтверждение —
билет с QR; отмена — с экрана билета (PAR-5). Чат-путь `myreg` выводится
из эксплуатации. Подробности — [BACKLOG W43](../BACKLOG.md#w43-регистрация-и-мои-билеты-в-каталоге-events),
дублировать не надо.

## Решение при взятии: серверный путь

**Новый sync-вебхук `reg-api`** (`initData` обязателен), действия:
`mine` — регистрации вызывающего; `register` — создать регистрацию
идемпотентно (IDM-1); `cancel` — отменить до `starts_at` (PAR-5). Почему не
расширение `reg-start`: у флоу ровно один триггер, а `reg-start` —
`callableFlow` чат-диалога; регистрация из Mini App — отдельное касание
([ADR-0015](../adr/0015-one-touch-one-flow.md)), сервер — вебхук
([ADR-0022](../adr/0022-miniapp-react-spa.md)). `my-qr-api` (QR по `initData`)
не трогается — «Показать QR» ведёт на `#/ticket?event_id=`, как в прототипе.

**`events-api` остаётся публичным** (ADR-0023: без `initData`) — «Мои билеты»
читает `reg-api`, персональные и публичные данные не смешиваются в одном
endpoint'е. `registerLink` в ответе `events-api` после переноса регистрации
на экран становится мёртвым — снимается тем же пакетом.

**Найдено противоречие при взятии (SPEC PAR-5 против вывода `myreg`).**
SPEC PAR-5: «Отмена — доступна до `starts_at`, **из чата** и с экрана
билета»; BACKLOG W43 (вердикт владельца 2026-09-16): «чат-карточка `myreg`
выводится из эксплуатации». Экран заменяет чат ([ADR-0017](../adr/0017-screen-not-message.md) п. 7,
[ADR-0025](../adr/0025-start-only-commands-ban.md)).

**Решение владельца 2026-09-16 (спрошен при взятии): отмена — только
в Mini App.** `my-regs` и `my-reg-cancel` удаляются; отмена доступна
на экране «Мои билеты» и на экране билета `#/ticket`; SPEC PAR-5 правится
отдельным коммитом со ссылкой на ADR-0017, в [`docs/OPEN-QUESTIONS.md`](../OPEN-QUESTIONS.md)
заводится запись с итогом. Слово «из чата» из PAR-5 уходит.

## Чек-лист готовности

> Скопирован из [BACKLOG.md](../BACKLOG.md#w43-регистрация-и-мои-билеты-в-каталоге-events).

- [ ] регистрация из каталога на опубликованном ивенте работает; различающие
      прогоны: дедлайн прошёл → отказ; мест нет → отказ; повтор → та же
      регистрация, второго подтверждения нет (IDM-1);
- [ ] PAR-2 по умолчанию `false` и не проставляется побочным эффектом (PAR-2);
- [ ] регистрация — только для владельца `initData`; `event_id` из запроса
      не даёт доступа к чужим данным и не создаёт регистрацию другому (IDOR);
- [ ] «Мои билеты» — только регистрации вызывающего; пустой срез — строкой
      ([VOICE](../VOICE.md));
- [ ] отмена из Mini App и из чата дают один результат; после `starts_at` —
      понятный отказ (PAR-5);
- [ ] `myreg`-путь выведен, `flows/` и каталог без него, `migrations` дописаны;
- [ ] экраны каталога сверены с прототипом-эталоном
      ([ADR-0027](../adr/0027-prototype-as-target-reference.md)): табы, карточки,
      шит регистрации с двумя согласиями, билет и его отмена; каждое отличие
      названо в журнале с причиной, самовольных добавлений и пропусков нет;
- [ ] `i18n/ru.json` и `check-texts.py` чисты; каталог обновлён;
- [ ] независимое ревью, вердикт «замечаний нет».

Плюс обязательный пункт: `catalog/` совпадает с живым проектом.

## Журнал

- **2026-09-16** — взятие пакета. Границы: новый `reg-api` (sync,
  `mine`/`register`/`cancel`), `events-api` без `registerLink`, SPA
  `Events.tsx` (три таба, шит PAR-1/PAR-2, строки билетов) и `Ticket.tsx`
  (отмена), `menu` («Мои регистрации» → `web_app #/events?tab=mine`),
  `tg-router` без колбэков `myreg:*`, удаление `my-regs` и `my-reg-cancel`,
  `i18n/ru.json`, `catalog/`, `flows/`, `migrations`, правка SPEC PAR-5
  отдельным коммитом. `reg-start` (глубокие ссылки и чат-регистрация)
  не трогается.
