  W33,W32,W34,W35`: 12 строк, поля `id`/`applied_at`/`package`/`object`/

- **Сверка полноты** — детерминированным скриптом `tools/check-migrations.py`
  (GET-only, ADR-0018): для каждой из 18 записей `flows/_manifest.json`
  последняя строка `publish` в `migrations` даёт `version_id ==
  publishedVersionId` и `object_id == flowId`; флоу без строк имеют `updated`
  раньше создания таблицы `migrations` (2026-09-14 05:08 UTC); `reg-phone` —
  единственный объект со строкой `delete` **в окне W33 → сейчас** (строки
  `delete` пакета W31 — более ранний набор объектов), его нет в
  `ap_list_flows` и в `flows/` репозитория.
- `ap_list_flows` — 18 флоу, все ENABLED/published; `flowIds` вставленных строк
  совпадают с живыми.
- **Скрипт ловит расхождение, а не только проходит** (негативные прогоны,

## Хвосты и блокеры

- `package: owner` — новая конвенция для изменений вне пакетов; при
  следующем изменении инстанса вне пакета писать так же.
- ПД в notes старых строк W31 (`w31-13/14`): вне пакета; `check-migrations.py`
  флагает предупреждением при каждом прогоне, чистить при следующем касании
  таблицы.
- Скрипт сверяет `publishedVersionId` и состав, но **не** содержимое
  `flows/<name>.json` с живой версией — это остаётся за `export-flows.sh`
  при выгрузке (свежесть снимка).
