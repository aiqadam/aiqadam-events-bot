## Цель

Контент SPA не должен заходить под собственную шапку Telegram (три точки,
имя приложения) и под вырезы/жестовую зону устройства. Реализация уже
открытого [Q48](../OPEN-QUESTIONS.md#q48). Подробности — [BACKLOG W48](../BACKLOG.md#w48-safe-area--отступы-под-системный-ui-telegram-q48),
дублировать не надо.

## Что построено

Только клиентский слой SPA, без flows/таблиц:

| Артефакт | Что изменено |
|----------|--------------|
| `miniapp/index.html` | `viewport-fit=cover` в `<meta name="viewport">` |
| `miniapp/src/index.css` | переменные `--safe-top`/`--safe-bottom`; `#root` (верх), `.sticky-actions`/`.app-sheet-panel` (низ) |

## Как проверено

> Чем именно, а не «протестировано».

- `npm run build` в `miniapp/` (`tsc -b && vite build`) — чисто, без ошибок
  типов и сборки, размеры чанков не изменились заметно.
- **Живой рендер в браузере не снят** — Playwright/Chrome в этой сессии
  зависал на подключении к локальному `vite preview` независимо от кода
  (сетевая особенность песочницы, воспроизвелась и на пустой странице без
  правок из этого пакета) — попытка не доведена до результата, не скрыта:
  проверка ограничилась статическим анализом CSS/HTML и `tsc`/`vite build`.
  Это не заменяет живую проверку на реальном устройстве с вырезом, которая
  и без этого — шаг владельца.
- Код-уровневый факт подтверждён без браузера: спецификация CSS Environment
  Variables — `env(safe-area-inset-*)` резолвится в `0`, если у документа
  нет `viewport-fit=cover`; в `miniapp/index.html` до этого пакета его не
  было, значит существовавшие `env()`-вызовы были мёртвым кодом на любом
  устройстве, включая уже якобы «покрытые» `.sticky-actions`/`.app-sheet-panel`.
