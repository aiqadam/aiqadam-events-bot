## Как проверено

Прогоны шли против **опубликованных** флоу напрямую `curl`
(`/api/v1/webhooks/<flowId>/sync`) с `Origin: https://miniapp.events.aiqadam.org`
(ответ содержал `access-control-allow-origin: *`, `OPTIONS`-preflight → `204` с
`access-control-allow-*`). `initData` посчитан временным флоу с двумя
`crypto : hmac-signature` на реальном `variables['BOT_TOKEN']` (приём W8),
подписи QR — `callFlow → fn-sign-qr` на реальном `QR_SIGNING_KEY`. Фикстуры
(`users`/`event_staff`/`registrations`) и временный флоу удалены после проверки.

`checkin-api` (контролёр с `users.lang=ru`):
`ok` → `{"status":"ok","name":"Aziz Test","text":"Aziz Test — отмечен"}` (записан
`checked_in_at`); повторный скан → `already`, `checkedInAtTashkent:"18:01"`,
`text:"Уже отмечен в 18:01"`, время не перезаписано (IDM-2); QR другого ивента →
`wrong_event` «Другой ивент»; несуществующий участник → `not_registered`
«Нет регистрации»; подделанная подпись → `invalid` «Код не распознан».
Контролёр с `users.lang=en` на том же «уже отмечен» → `"Already checked in at 18:01"`
(язык — контролёра из `users`, не Telegram). Участник вместо контролёра → `403`
`forbidden` «Нет прав на чекин этого ивента» (STF-2). Мусорный `initData` → `401`
`invalid_init_data` «Данные Mini App устарели — переоткройте приложение».

`my-qr-api`: зарегистрированный участник → `ok:true` с `payload`, совпавшим с
`fn-sign-qr`; участник без регистрации (`lang=ru`) → `not_registered` «Нет
регистрации»; другой пользователь `lang=en` без регистрации → «Not registered»
(язык из `users`); мусорный `initData` → `invalid_init_data` «Данные Mini App
устарели — переоткройте приложение».

Синтаксис JS страниц проверен `node --check`; JSON словарей валиден.

Про происхождение языка текста: серверный `text` берётся **исключительно** из
`users.lang` (`checkin-api/step_6`, `my-qr-api/step_16` читают только поле `lang`
строки `users`; `initData.language_code` в шагах нигде не читается), поэтому
различающая фикстура `users.lang ≠ language_code` не нужна — регрессия на чтение
`language_code` структурно невозможна, а не просто не поймана прогонами.

1. **на будущее** — `.github/workflows/pages.yml`: артефакт теперь включает

2. **на будущее** — AppSec 4.4/Q17: W7 добавил чтение полной строки `users` на
   каждый вызов. `checkin-api/step_28` читает строку контролёра при каждом скане —
   язык нужен во всех пост-авторизационных ветках, неустранимо без проекции (Q17).
   А вот `my-qr-api/step_15` стоит **до** роутера `step_7` и исполняется и в ветке
   `ok`, где `lang` (`step_16`) не используется вовсе — полная строка вызывающего

   тикета. Перенос `step_15`/`step_16` внутрь ветки `Otherwise` (`not_registered`)

   собственные, класс риска принят в Q17.
3. **на будущее** — e2e-прогоны не различают источник языка: у всех фикстур

   их все. По чтению кода (`step_6`/`step_16` читают только поле `lang` из `users`)
   реализация верна; для закрепления нужна различающая фикстура

4. **на будущее** — формулировки расходятся с кодом. (а) Чек-лист в журнале: на
