## Цель

Рассылки (OWN-9…OWN-13). Headline-UX (решение владельца 2026-09-15):
овнер **пересылает боту готовое сообщение**, бот рассылает сегменту.
Подробности — [BACKLOG W14](../BACKLOG.md#w14-рассылки).

## Предрешено до сборки (не требует будить владельца)

- **Q13**: замер темпа — временным флоу-циклом (50 итераций + `delay`),
  форма ошибки — шагом с неверным `chat_id`. При подтверждении ~1 msg/s
  срабатывает решение 2026-09-08: снизить темп до реального и поправить
  OWN-11 отдельным коммитом в SPEC. Параллельные чанки отклонены (Q13).
- **Q18**: канал «фоновый флоу ничего не сделал» — сообщение овнеру ивента
  в бот по завершении (успех/пустой сегмент/провал); детали — на сборщике,
  с записью в журнал.
- **Q51-аналога нет**; сегменты — по SPEC OWN-9 (включая `no_show` только
  при `now >= ends_at`, отказ с объяснением).

## Журнал

- **2026-09-17** — пакет взят (ветка `w44-staff-search`, единый PR v0.1).
  W13-ревью зафиксировано (2 «важно» исправлены). Сборка делегирована

- **2026-09-17** — разведка перед сборкой (целиком: SPEC OWN-9…OWN-13,
  DATA-MODEL broadcasts/targets/sessions, VOICE, каталог, прототип
  `app.js:1026` + `scenarios.js:141` (пересылка→сегмент→preview→test→send→
  finished/unsub; `st-bcast-noshow/empty/cancelled`), W13-гейт staff-границы).
  Решения по дизайну (все — в карточках, здесь перечень):
  1. Флоу: `bcast-draft` (пересылка→черновик+выбор ивента/сегмента),
     `bcast-step` (колбэки `ev/seg/test/send/cancel`, ADR-0016 — одна
     последовательность одинаковых вопросов), `bcast-unsub` (отписка
     получателя, без staff-гейта), `bcast-run` (чанки по 30 с курсором,
     самовызов очередью), `tmp-w14-rate-probe` (замер Q13, до вердикта).
  2. Пересылка видна роутеру только после правки `step_1` (сейчас forward
     не извлекается) — `forwarded`+`fwdText` (`text||caption`, `parse_mode`
     черновика всегда `None`: форматирование пересылки не переносим,
     овнер видит ровно то, что уйдёт, на тесте).
  3. Маршрутизация — по префиксу `bcast:*` (как `reg:pdn:`), staff-гейт —
     внутри флоу (не-staff пересылка уходит в тишину, не в `Otherwise`
     с письмом: форварды от гостей — обычное дело).
  4. Сегменты 2–4 (`registered/attended/no_show`) — без требования
     `consent_marketing` (адресное инфо по ивенту, не анонсы);
     `all_consent` — только `consent_marketing=true`; `blocked_bot=true`
     исключён из всех сегментов; кнопка отписки — в каждом массовом.
     Черновик всегда привязан к ивенту (пустой `event_id` не используем).
  5. Темп — `delay 1s` между отправками (последовательный цикл быстрее
     ~1,4 msg/s физически не может; задержка — вежливость, не соблюдение
     лимита). Число — из замера Q13, OWN-11 правится по нему.
  6. `429` — пауза на `retry_after` из формы замера + 1 повтор; `403` —
     `blocked_bot=true` (upsert `users`) + `blocked` в таргете.
  7. Q18 — вариант 1: отчёт сообщением на `events.staff_id` (автор ивента)
     всегда: успех (`sent/failed`), пустой сегмент, провал/стоп.
     Прогресс-карточка не редактируется (лишние отправки).
  8. Новые ключи `ru.json` (7): `bcast.ask.event`, `bcast.btn.cancel`,
     `bcast.btn.seg_all/registered/attended/noshow` (короткие, VOICE ≤23),
     `bcast.interrupted`. Кнопки сегментов — короткие формы, полные имена
     остаются в тексте экрана (как в прототипе).
