## Журнал

- **2026-09-21** — пакет взят (ветка `w12b-dedup-report`).
- **2026-09-21 — решения при сборке.**
  1. **Диагностика без побочных эффектов.** Четыре шага — `tables-find-records`,
     затем `CODE`, затем цикл отправки. Ни одного `tables-*-record(s)`-записи
     и ни одного удаления: это и есть сужение Q42 (вариант 2), а не случайность.
  2. **«Число дублей» = «лишние строки»** — сумма `n−1` по ключам, встретившимся
     больше одного раза. Это отвечает на вопрос «сколько строк сверх нормы»,
     а не «сколько пар задвоено». Строка с пустой половиной ключа не судится.
  3. **Получатель — строки `staff`.** Проектного канала «владелец» в проекте
     нет ([Q18](../OPEN-QUESTIONS.md#q18): «списка админов нет»), `staff` —
     единственный список, который ведёт человек ([ADR-0024](../adr/0024-staff-by-chapter-event-staff-checkin.md)),
     и сейчас это ровно одна строка — владелец проекта. Так выбран источник,
     который не жёстко зашит в флоу и не требует новой переменной; получатели
     дедуплицируются. Пустой `staff` — ноль итераций цикла, тишина.
  4. **Читаются только ключевые колонки** (`columns`), вся таблица — без
     `limit` (проверено: `limit` не обязателен). `telegram_id` в логе есть —
     без него счёт невозможен; в **сообщении** только имена таблиц и счётчики.
     Потолок чтения не вводился: диагностике нужна полнота, а не экономия лога.
  5. **Тексты — в `i18n/ru.json`** (`dedup.*`), в шаге только ссылки, как во
     всех живых флоу после W24; ключи сверяет `check-texts.py`.
  6. **Дата — Asia/Tashkent** (`Intl ru-RU`, `DD.MM.YYYY`), иначе прогон 03:00
     по Ташкенту показывал бы вчерашнюю UTC-дату (OWN-3).
- **2026-09-21 — ход сборки.** `ap_build_flow` собрал 8 шагов за один вызов
  (триггер + 4 чтения + CODE + LOOP + send), `ap_validate_flow` чист сразу.
  Сначала прогнан локальный харнесс на теле CODE, затем два живых прогона
  (дубль заведён/снят). Публикация — после прогонов, экспорт — сразу после
  неё. Оба тестовых прогона отправили диагностическое сообщение владельцу в
  Telegram — это и есть проверка доставки («тест себе», OWN-10-по-духу);
  после снятия дубля сообщение показывает нули.
- **2026-09-21 — DATA-MODEL.** Два present-tense упоминания `dedup-sweep`
  в разделе «Идемпотентность» заменены на действительность: дубли **считает**
  `dedup-report`, ключи `upd:*` истекают по TTL (ADR-0011). Исторические
  упоминания в ADR, BACKLOG и журналах не трогались.
