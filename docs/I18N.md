# Локализация

Языки: **ru / uz / en** (I18N-1). Дефолт — `ru`.

## Правило

**Ни одной пользовательской строки литералом** — ни в Code step, ни в поле `sendMessage`,
ни в подписи кнопки (I18N-2). Везде только ключ, текст достаётся через `fn-t`.

Нарушение видно сразу: если в JSON флоу встречается кириллица или узбекская латиница
в тексте сообщения — это баг локализации, а не «мелочь, потом вынесем».

## Где живут строки

Каноничный источник — файлы в этом репозитории:

```
i18n/
  ru.json
  uz.json
  en.json
```

Плоские ключи, точка как разделитель уровней:

```json
{
  "reg.consent_pdn.ask": "Для регистрации нужно согласие на обработку данных.",
  "reg.consent_pdn.button_agree": "Согласен",
  "reg.consent_marketing.ask": "Присылать анонсы будущих ивентов?",
  "reg.consent_marketing.button_no": "Нет, спасибо",
  "checkin.ok": "{name} — отмечен",
  "checkin.already": "Уже отмечен в {time}",
  "checkin.not_registered": "Нет регистрации",
  "checkin.wrong_event": "Другой ивент"
}
```

Подстановки — `{name}`, `{time}`, `{title}`. Никакой логики внутри строк
(ни условий, ни вложенных шаблонов).

## Как строки попадают в флоу

Файлы синхронизируются в таблицу `strings` (`key`, `lang`, `value`),
откуда их читает `fn-t`. Репозиторий — источник правды, таблица — рабочая копия;
правка текста в таблице мимо репозитория переживёт ровно до следующей синхронизации.

Синхронизация — отдельный флоу `i18n-sync`: тянет JSON по HTTP из репозитория
и делает upsert в `strings`. Способ доставки файлов (raw.githubusercontent, релиз,
ручная загрузка) — [Q5](OPEN-QUESTIONS.md#q5).

## `fn-t`

Вход: `key`, `lang`, `vars`. Порядок разрешения:

1. `(key, lang)`;
2. `(key, "ru")` — фолбэк;
3. сам `key` как текст — чтобы отсутствие перевода было заметно, но ничего не падало.

Отсутствующие ключи стоит собирать в лог: пустой экран хуже, чем сырой ключ на экране.

## Выбор языка

`users.lang`. Первичное значение — из `language_code` апдейта Telegram, если это
`ru`/`uz`/`en`, иначе `ru`. Пользователь может сменить язык командой; выбор
сохраняется и применяется ко всем последующим сообщениям, включая рассылки.

## Замечания по конкретным языкам

- **uz** — латиница (`oʻ`, `gʻ` с модификатором `ʼ`, U+02BB/U+02BC). Не подменять
  их апострофом `'`: это разные символы, и поиск по строкам поедет.
- **Даты** рендерит `fn-fmt-time` через `Intl.DateTimeFormat` с таймзоной
  `Asia/Tashkent` (OWN-3) и локалью пользователя. Форматы дат не хардкодятся в строках.
- Числа и склонения («3 участника» / «5 участников») — держим формулировки, не требующие
  плюрализации, пока не появится реальная необходимость.
