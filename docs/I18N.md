# Локализация

> **Актуальность (2026-09-13, W22).** Ниже логика описана через
> subflow-«функции» `fn-*`. **Этих флоу больше нет** — [ADR-0012](adr/0012-end-to-end-flows-instead-of-subflow-functions.md)
> отменил их как практику (W21 убрал все вызовы, W22 удалил сами флоу).
> Читайте `fn-<имя>` как «шаг по эталону
> [`catalog/snippets/<имя>`](../catalog/snippets/), встроенный в тело флоу».
> Требования от этого не изменились — изменилось только то, где живёт код.
> Единственный оставшийся `callFlow` в проекте — `tg-router` → `registration`.

Языки: **ru / uz / en** (I18N-1). Дефолт — `ru`.

## Правило

**Ни одной пользовательской строки литералом** — ни в Code step, ни в поле `sendMessage`,
ни в подписи кнопки (I18N-2). Везде только ключ, текст достаётся через `fn-t`.

Нарушение видно сразу: если в JSON флоу встречается кириллица или узбекская латиница
в тексте сообщения — это баг локализации, а не «мелочь, потом вынесем».

## Где живут строки

Каноничный источник — файлы в этом репозитории:

```
i18n/
  ru.json
  uz.json
  en.json
```

Плоские ключи, точка как разделитель уровней:

```json
{
  "reg.consent_pdn.ask": "Для регистрации нужно согласие на обработку данных.",
  "reg.consent_pdn.button_agree": "Согласен",
  "reg.consent_marketing.ask": "Присылать анонсы будущих ивентов?",
  "reg.consent_marketing.button_no": "Нет, спасибо",
  "checkin.ok": "{name} — отмечен",
  "checkin.already": "Уже отмечен в {time}",
  "checkin.not_registered": "Нет регистрации",
  "checkin.wrong_event": "Другой ивент"
}
```

Подстановки — `{name}`, `{time}`, `{title}`. Никакой логики внутри строк
(ни условий, ни вложенных шаблонов).

## Как строки попадают в флоу

Файлы синхронизируются в таблицу `strings` (`key`, `lang`, `value`),
откуда их читает `fn-t`. Репозиторий — источник правды, таблица — рабочая копия;
правка текста в таблице мимо репозитория переживёт ровно до следующей синхронизации.

Синхронизация — отдельный флоу `i18n-sync`: тянет JSON по HTTP и приводит
`strings` к содержимому файлов. Источник — **`raw.githubusercontent.com`,
ветка `main`** (решено):

```
https://raw.githubusercontent.com/aiqadam/aiqadam-events-bot/main/i18n/ru.json
```

Репозиторий публичный, токен не нужен. Строки обновляются после мержа запуском
`i18n-sync` (вручную или по расписанию).

Правка строки прямо в таблице `strings` мимо репозитория проживёт до следующей
синхронизации — чинить опечатку нужно в JSON, а не в UI.

### Почему не upsert (уточнено в W3)

Upsert'а в Tables нет, уникальных индексов тоже
([ARCHITECTURE](ARCHITECTURE.md#tables-на-практике--проверено-на-инстансе-2026-09-08)),
поэтому `i18n-sync` считает **диф**: читает таблицу целиком, сравнивает с файлами
и раскладывает разницу на «создать» / «обновить» / «удалить». Отсюда четыре свойства,
на которые опираются остальные пакеты:

1. **Повторный прогон ничего не меняет** — второй запуск подряд даёт нулевой диф.
   Дубликатов не появляется, хотя БД их и не запрещает.
2. **Дубли `(key, lang)`, если они как-то возникли, вычищаются**: остаётся одна
   строка, лишние удаляются (в духе [ADR-0003](adr/0003-idempotency-without-atomicity.md)).
3. **Языки независимы.** Если файл языка не скачался (404, 5xx, битый JSON),
   этот язык не трогается вовсе — ни удалений, ни правок. Иначе одна ошибка сети
   оставила бы бота без строк.
4. **Мусорные строки** — с `lang` вне `ru`/`uz`/`en` или с пустым `key` —
   удаляются, но только если хотя бы один язык в этом прогоне доехал. Если легли
   все три файла, прогон не меняет таблицу ни на одну запись.

### Предохранитель: обрезанный файл не стирает язык

Отказ сети — не единственный способ потерять строки, и даже не самый вероятный.
**HTTP 200 с валидным, но пустым или обрезанным JSON** («`{}`» после неудачного
мержа, файл, сохранённый наполовину) формально корректен: язык считается
доехавшим, `wanted` пуст, и все строки этого языка уезжают в удаление.
Для `ru` это потеря единственного фолбэка — бот покажет сырые ключи во всём
интерфейсе.

Поэтому `i18n-sync` не трогает язык, если в файле:

- **ноль** пригодных ключей — всегда, даже когда таблица пуста;
- **меньше половины** того, что уже лежит в таблице по этому языку.

Это **растяжка, а не бизнес-правило**, и у неё есть цена: осознанное сокращение
словаря больше чем вдвое одним прогоном не пройдёт — его придётся провести
в два шага или временно снять порог. Цена принята сознательно: словарь
сокращается вдвое раз в жизни проекта, а обрезанный файл — правдоподобная
случайность любого дня.

Сравнение идёт по **числу различных ключей**, а не записей: иначе
размножившиеся дубли раздули бы порог, и язык заблокировался бы вместе
с дедупом, который эти дубли и убрал бы, — предохранитель запирал бы дверь
снаружи ровно в той ситуации, для которой задуман.

Сработавший порог виден в `skipped_langs` вместе с числами («в файле 67 ключей
против 203 ключей в таблице»), и прогон при этом остаётся успешным.

### Пустых значений в `strings` не бывает

Ключ, которого нет в файле языка, **не заводится** в `strings` пустой строкой.
Это не мелочь: `fn-t` отличает «строки нет» от «строка пустая» только по факту
отсутствия записи, и пустое значение сломало бы фолбэк — вместо русского текста
пользователь получил бы пустое сообщение. `i18n-sync` пустые `value` отбрасывает
и сообщает о них в отчёте прогона.

Обратная сторона того же правила: **`ru.json` обязан быть полным.** Это
единственный язык, на который есть фолбэк; ключ без русского значения падает
до сырого ключа на экране. Ключи, которые есть в `uz`/`en` и отсутствуют в `ru`,
`i18n-sync` считает дефектом и выводит отдельным списком.

### Служебные ключи `_selftest.*`

Ключи с префиксом `_selftest.` пользователю не показываются и во флоу
не используются. Это фикстуры:

| Ключ | Зачем |
| --- | --- |
| `_selftest.vars` | подстановка `{a}` / `{b}` — проверка `fn-t` без риска задеть живой текст |
| `_selftest.fallback` | **есть только в `ru`** — постоянная фикстура фолбэка |

`_selftest.fallback` заведён намеренно и намеренно не переведён: правило
«отсутствующий перевод падает в `ru`» иначе проверяется только на глаз.
Пользовательского текста он не содержит, поэтому цена фикстуры — нулевая.

## `fn-t`

Вход: `key`, `lang`, `vars`. Порядок разрешения:

1. `(key, lang)`;
2. `(key, "ru")` — фолбэк;
3. сам `key` как текст — чтобы отсутствие перевода было заметно, но ничего не падало.

Отсутствующие ключи стоит собирать в лог: пустой экран хуже, чем сырой ключ на экране.

Уточнения контракта (зафиксированы в W3, реализация — W2):

- `lang` вне `ru`/`uz`/`en` обрабатывается как отсутствующий перевод, то есть
  сразу пункт 2. Валидировать язык на входе не нужно, но и молча отдавать
  пустоту нельзя;
- `vars` — **плоский** объект строк, подстановка одним проходом: `{name}`
  в значении заменяется на `vars.name`;
- плейсхолдер, которого нет в `vars`, остаётся в тексте как есть (`{name}`).
  Это заметный дефект, и он должен быть заметным — подставлять пустоту хуже;
- подставленное значение **не интерпретируется**: `{name}`, приехавший из `vars`,
  не может внести новый плейсхолдер, второго прохода нет.

## Разметка: строки — простой текст

Строки не содержат разметки Telegram, и `parse_mode` для них не выставляется.
Причина не в эстетике: в `{name}`, `{title}`, `{address}` приезжает
пользовательский ввод, и при включённом `Markdown`/`HTML` один символ `_`
в имени участника ломает сообщение целиком, а `<a href>` в названии ивента
превращается в ссылку. Нужен акцент — он делается структурой сообщения
(отдельная строка, кнопка), а не звёздочками.

## Выбор языка

`users.lang`. Первичное значение — из `language_code` апдейта Telegram, если это
`ru`/`uz`/`en`, иначе `ru`. Пользователь может сменить язык командой; выбор
сохраняется и применяется ко всем последующим сообщениям, включая рассылки.

## Замечания по конкретным языкам

- **uz** — латиница (`oʻ`, `gʻ` с модификатором `ʼ`, U+02BB/U+02BC). Не подменять
  их апострофом `'`: это разные символы, и поиск по строкам поедет.
  В `uz.json` ASCII-апострофа нет ни в одном значении — это проверяемое свойство файла.
- **Даты** рендерит `fn-fmt-time` через `Intl.DateTimeFormat` с таймзоной
  `Asia/Tashkent` (OWN-3) и локалью пользователя. Форматы дат не хардкодятся в строках.
- Числа и склонения («3 участника» / «5 участников») — держим формулировки, не требующие
  плюрализации, пока не появится реальная необходимость.
