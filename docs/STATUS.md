# Статус проекта

Индекс работ. **Одна строка на пакет** — так параллельные агенты правят разные
строки, и git сливает их без конфликтов. Подробности каждого пакета —
в его журнале `docs/work/WNN-*.md` ([правила ведения](work/README.md)).

Статусы: `не начат` · `в работе` · `заблокирован` · `на проверке` · `готов`.

`на проверке` — пакет доведён и ждёт **независимого ревьюера**; `готов` ставится
только после вердикта «замечаний нет». Сдать пакет самому себе нельзя —
[правила](work/README.md#цикл-сдачи).

файлом вовсе, а рендерится клиентским JS в новой странице `miniapp/ticket.html`

(`I5nd8ggKH4wkQLaww9Dkl`) после проверки `initData` — проверено настоящей
криптографией (не моками) и прямым `curl` на публичный эндпоинт. Независимое
ревью прошло два круга: первый нашёл одно замечание уровня «важно» (вторая
статическая страница Mini App с литеральными русскими строками без ссылки
на уже открытый [Q19](OPEN-QUESTIONS.md#q19) — устранено расширением Q19 на
обе страницы), второй дал вердикт «замечаний нет». Пакету поставлен статус
`готов`. Живое состояние —
[catalog/flows/registration.md](../catalog/flows/registration.md),
[catalog/flows/tg-router.md](../catalog/flows/tg-router.md),

## Что сделано помимо пакетов

- **Документы.** ТЗ ([SPEC.md](SPEC.md)) с нумерованными требованиями, архитектура,
  модель данных, флоу, безопасность, i18n, бэклог, roadmap.
- **Решения.** ADR-0001 (Qadam Flow как несущий стек, «0 кода»), ADR-0002 (роли таблицами),
  ADR-0003 (идемпотентность без атомарных примитивов), ADR-0004 (агентский каталог),
  ADR-0005 (секреты в логах прогонов — цена, а не дефект), ADR-0006 (REST на чтение
  ревьюеру там, где MCP слеп), ADR-0007 (QR участника рендерится в Mini App,
  не отправляется файлом через Telegram).
- **Открытые вопросы.** Из 21 закрыты 16 (полностью или для текущих пакетов).
  Открыты: [Q13](OPEN-QUESTIONS.md#q13) (25 msg/s, блокер W14),
  [Q14](OPEN-QUESTIONS.md#q14) (адресация dev/prod в сканере, блокер W7),
  [Q16](OPEN-QUESTIONS.md#q16) (**живой `initData` — нужен человек**, блокер
  приёмки STF-2 в W8), [Q17](OPEN-QUESTIONS.md#q17) (ПД в логах: у `tables`
  нет проекции колонок — принятый риск), [Q18](OPEN-QUESTIONS.md#q18) (как узнаём,
  что фоновый флоу не сделал работу — до W14), [Q19](OPEN-QUESTIONS.md#q19)
  (локализация Mini App — до W7), [Q21](OPEN-QUESTIONS.md#q21) (**FILE-пропы не
  резолвятся через MCP ни на одном qadam'е** — общий предел платформы, актуален
  для W7/W12, если понадобится передать файл через MCP-собранный шаг).
  [Q20](OPEN-QUESTIONS.md#q20) (`callFlow` с данными не настраивался через MCP —
  блокер W5, W10, W11) закрыт 2026-09-09: дело было не в платформе, а в форме
  `input.flow` при резолве `ap_get_piece_props` (нужен объект с `exampleData`, не
  строка); настоящее подполе — `flowProps.payload`. W5, W10, W11 разблокированы
  для передачи данных в subflow'ы. Q21 для **W5** закрыт тем же днём —
  [ADR-0007](adr/0007-qr-rendered-in-miniapp.md): QR рендерится в Mini App, не
  отправляется файлом, так что найденный предел платформы W5 больше не блокирует.
- **MCP.** Проектный сервер `qadam-flow` подключён по OAuth.
- **Практики.** Принята модель `qadam-flow-project-template`: MCP + UI, плюс
  read-only REST ревьюеру (ADR-0006). Правила, выведенные из пяти кругов ревью W3
  и трёх кругов W2, живут в [work/README.md](work/README.md): доказательство
  копируется в журнал до удаления флоу; доказателен только прогон **после**
  `ap_lock_and_publish`; правя утверждение о состоянии, читай файл целиком —
  вторая копия бывает в том же файле.
