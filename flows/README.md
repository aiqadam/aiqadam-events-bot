# Экспорт флоу

Здесь лежат **опубликованные** версии флоу проекта. Два способа снять
снимок: `GET /api/v1/flows/:id?versionId=<publishedVersionId>`
([ADR-0018](../docs/adr/0018-rest-read-for-everyone.md) п. 3,
`tools/export-flows.sh`) или `ap_export_flow` через MCP **сразу после
`ap_lock_and_publish`** ([ADR-0021](../docs/adr/0021-repo-is-source-of-truth-migrations-table.md),
`tools/export-flow-mcp.py`, в манифесте `source: "mcp"`). Смысл один:
`settings.input` PIECE-шагов (URL, cron, таймзоны, `format`, порядок
аргументов `hmac-signature`) виден в диффе PR, а не только тому, кто
специально сходил в REST.

**Почему не `/flows/:id/template`.** Тот эндпоинт молча игнорирует
`versionId` и всегда отдаёт **последнюю** версию: ответ побайтово одинаков
при `versionId` опубликованной версии, черновика, при отсутствующем
параметре и при заведомо несуществующем `versionId`. На 2026-09-14 у 14 из
22 флоу проекта последняя версия не совпадала с опубликованной.

**Чем доказывается, что снимок с опубликованной версии.** Не самим файлом:
`"state": "LOCKED"` в нём означает лишь «версия заморожена», а замороженной
бывает и неопубликованная — у `reg-consent-mkt` таких две, опубликована
одна. Доказательство даёт **момент выгрузки**: скрипт сверяет `version.id`
из ответа с `publishedVersionId` и пропускает флоу, если не сошлось, —
проверяется факт, а не то, что мы передали нужный параметр. Снаружи это
подтверждается `_manifest.json`, где записан `publishedVersionId` каждого
флоу; сверять его с `ap_list_flows` — отдельный пункт чек-листа ревьюера.
Из самого файла версию узнать нельзя: нормализация выбрасывает `.id`.

## Снимок через MCP (ADR-0021)

Когда ключа платформы нет, снимок снимается `ap_export_flow` **сразу после
`ap_lock_and_publish`**, до любой правки черновика, и кладётся сюда
`tools/export-flow-mcp.py` в той же нормализованной форме. В `_manifest.json`
такая запись несёт `source: "mcp"`. Отличия от REST-снимка, которые видны
диффом и не являются изменением конфигурации: **нет полей `auth` в шагах**
(`connectionIds` на уровне флоу сохранён) и **нет пустых строк в
`exampleData`**. Перевыгрузка REST-скриптом возвращает полную форму.
Факт «инстанс равен репозиторию» записывается в таблицу `migrations`
([catalog/tables/migrations.md](../catalog/tables/migrations.md)).

## Правила

- **Руками эти файлы не правятся никогда.** Они машинные. Правка флоу идёт
  через MCP, затем снимается новый снимок.
- **Обновляются тем же коммитом, что и изменение флоу** (ADR-0018 п. 5).
  Протухший снимок хуже отсутствующего: по нему принимают решения.
- **Это снимок, а не реальность.** Ревьюер по-прежнему сверяет каталог
  с живым проектом через MCP, а `flows/_manifest.json` — с `ap_list_flows`:
  параллельный пакет мог опубликовать свои флоу после того, как снимок сняли.
- **Тексты сверяются с `i18n/ru.json`** отдельно:
  `python3 tools/check-texts.py i18n/ru.json flows/*.json` (ADR-0014 —
  у текста два источника правды, и это ловит их расхождение).
- **Экспорт нормализован** ([Q39](../docs/OPEN-QUESTIONS.md#q39)): выброшены
  `lastUpdatedDate`, `lastTestDate`, `sampleDataFileId` и версионные
  `created`/`updated`/`id`/`flowId`/`updatedBy`. Без этого публикация **без
  единой смысловой правки** давала 22–36 изменённых строк на флоу. Список
  выбрасываемого — в `tools/export-flows.sh`, переменная `NORMALIZE`;
  `settings.input` не трогается вовсе.
- Экспорт отдаёт **опубликованную** версию. Прогоны `TESTING` исполняют
  draft — равенство draft и published доказывается процедурой (публикация,
  затем прогон, без правок между), а не этим файлом.

## Как снять и как проверить

```bash
tools/export-flows.sh              # все флоу проекта
tools/export-flows.sh checkin-api  # или только нужные
tools/check-export-secrets.sh      # ОБЯЗАТЕЛЬНО перед коммитом
```

`check-export-secrets.sh` возвращает ненулевой код, если:

- нашёлся паттерн токена Telegram или hex-строка ≥32 символов;
- из экспорта пропали ссылки `{{variables['...']}}` — значит форма выгрузки
  изменилась, и «ноль совпадений» больше ничего не доказывает: ноль бывает
  и оттого, что секрет подставлен значением под другим именем;
- хоть одно поле `auth` **не** в форме `{{connections['<externalId>']}}`.
  Ссылка — норма и то, что [Q38](../docs/OPEN-QUESTIONS.md#q38) признал
  безопасным: `externalId` connection'а публичен и уже лежит в `catalog/`.
  Блокер — значение вместо ссылки.

Сканируются **только `*.json`**. Этот README сюда не входит намеренно:
формы ссылок приведены в нём как текст, и однажды позитивный контроль
прошёл именно на нём — «ok», который ничего не значил.

Проверка **повторяемая, а не сделанная один раз**:
[Q38](../docs/OPEN-QUESTIONS.md#q38) зафиксировал поведение текущего образа
платформы, а не гарантию на будущее. Секрет, уехавший в историю git, не
откатывается удалением файла — он откатывается ротацией `BOT_TOKEN`
и `QR_SIGNING_KEY`.

## Два пути выгрузки: REST-скрипт и `ap_export_flow`

С qadam-flow PR #439 у платформы есть MCP-путь `ap_export_flow` той же формы
`SharedTemplate`. Он отдаёт **последнюю** версию флоу, выбора версии у него
нет ([Q44](../docs/OPEN-QUESTIONS.md#q44)); поэтому он годится **только с
условием «сразу после `ap_lock_and_publish`, без правок черновика»** — тогда
последняя версия и есть опубликованная, `flows[0].id` равен
`publishedVersionId`, `state: LOCKED`, и `tools/export-flow-mcp.py` это
проверяет и отказывается писать иначе (ADR-0021, раздел выше). Снимок беднее
REST-снимка: без `auth` в шагах и без пустых строк `exampleData`.
С ключом платформы предпочтителен `tools/export-flows.sh`: он снимает любую
опубликованную версию в любой момент и в полной форме.

## Ключ платформы

В репозитории его нет и не будет. Скрипт берёт ключ из `QADAM_API_KEY`, иначе
из macOS Keychain (сервис `aiqadam-events-bot:qadam-flow-api`), и передаёт
в `curl` по stdin — ключ не попадает ни в вывод, ни в `ps`, ни в историю
оболочки. Агенту Claude Code для чтения Keychain нужно разрешение
`Bash(security find-generic-password:*)` в `.claude/settings.local.json`.
